# Gap 01: 原子工具层缺失

## 状态
❌ **未实现**

## 问题描述

AgentFlow **没有任何给 agent 使用的原子工具**（如 read file、write file、bash、grep 等）。当前范例 agent（harness-agent）只有一个测试用的 `echo` 工具，且是 Python 进程内临时注册的，不是框架级能力。

## 对比

| 能力 | Claude Code | AgentFlow |
|------|:-----------:|:---------:|
| Read / 读文件 | ✅ | ❌ |
| Write / 写文件 | ✅ | ❌ |
| Edit / 编辑文件 | ✅ | ❌ |
| Bash / 执行命令 | ✅ | ❌ |
| Grep / 搜索文件内容 | ✅ | ❌ |
| Glob / 搜索文件 | ✅ | ❌ |
| WebSearch / 网络搜索 | ✅ | ❌ |
| **总共工具数** | **~15 个** | **0 个** |

## 影响

- 开发者无法直接让 agent 执行任何实际操作（文件读写、命令执行）
- 每个使用场景都需要用户自行编写 tool node（Python/Shell 脚本）
- 没有开箱即用的 agent 体验

## 根因

AgentFlow 定位为**编排框架**，只提供了：
- Workflow 执行引擎 ✓
- DataBus / UDS 通信 ✓
- 多语言节点执行能力 ✓
- JSON-RPC 管理接口 ✓

但**没有内置任何原子工具**——工具逻辑需要用户自己实现。

## 建议方向

在框架层提供一组内置 atom tool，可作为 skill 或 workflow 被 agent 调用：

| 工具 | 实现方式 | 优先级 |
|------|---------|--------|
| `bash` | Shell script node | P0 |
| `read_file` | C++ function / Python node | P0 |
| `write_file` | C++ function / Python node | P0 |
| `glob` | Shell script node | P1 |
| `grep` | Shell script node | P1 |
| `web_search` | Python node (requests) | P1 |
