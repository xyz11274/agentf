# Gap 05: 管理界面缺失

## 状态
❌ **未实现**

## 问题描述

AgentFlow 的 daemon（`agentflowd`）提供了完整的 JSON-RPC 管理接口（18+ 个方法，覆盖 agent/session/workflow/runtime 管理），但**没有任何 Web UI** 来使用这些接口。

## 现有前端 vs 缺失的前端

### 已有（离线分析工具）

| 工具 | 位置 | 功能 |
|------|------|------|
| DSL Visualizer | `publish/agent/visualizer.html` | 看 workflow JSON 的节点图 |
| Flow Trace Viewer | `tools/flow_trace_viewer/` | 看调度追踪日志的时序图 |
| Span Trace Viewer | `tools/span_trace_viewer/` | 看 span 耗时和火焰图 |

### 缺失（运行时管理界面）

| 功能 | 对应 JSON-RPC 方法 | 说明 |
|------|-------------------|------|
| Agent 管理 | `agent.list / load / unload / execute` | 查看运行中的 agent、发送请求 |
| Session 管理 | `session.list / destroy` | 查看活跃会话 |
| Workflow 监控 | `workflow.list / info / list_instances` | 查看运行中的 workflow |
| 运行时状态 | `runtime.status / health` | 实时健康监控 |
| 事件推送 | `event.subscribe` | 实时日志/事件推送 |
| Workflow 编辑器 | — | 可视化创建/编辑 workflow JSON |

## 影响

- 运维人员需要 `nc` 或手写脚本来管理 daemon
- 无法快速查看 daemon 运行状态
- 没有可视化 workflow 编辑工具（当前全靠手写 JSON）
- 不利于非技术用户使用

## 建议方向

利用已有的 WebSocket 支持和 JSON-RPC 接口，构建一个 Web 管理后台：

```
Web UI（Vue/React）
    │ WebSocket / HTTP
    ▼
agentflowd (TCP 7890)
    ├── WebSocket 升级 ← 支持服务端推送
    ├── JSON-RPC 方法 ← 全量管理能力
    └── event.subscribe ← 实时事件流
```
