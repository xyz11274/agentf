# Gap 07: 分布式通信缺失

## 状态
❌ **未实现**

## 问题描述

AgentFlow 框架**未内置 Master-Worker 网络通信**。当前 daemon 只能单机运行，Master 和 Worker 在同一进程中。

## 当前架构

```
┌─────────────────────────┐
│     agentflowd          │
│  ┌───────────────────┐  │
│  │ Master (内置)      │  │
│  │  ├─ 调度器         │  │
│  │  └─ 部署器         │  │
│  └───────────────────┘  │
│  ┌───────────────────┐  │
│  │ Worker (内置/本地) │  │
│  │  ├─ Workflow 执行   │  │
│  │  └─ 进程管理       │  │
│  └───────────────────┘  │
└─────────────────────────┘
```

## 对比：理想分布式架构

```
┌──────────┐    网络通信    ┌──────────┐
│ Master    │◀────────────▶│ Worker 1 │
│ (调度+部署) │              │ (执行节点) │
│           │              ├──────────┤
│           │              │ Worker 2 │
│           │              ├──────────┤
│           │              │ Worker N │
└──────────┘              └──────────┘
```

## 代码现状

```cpp
// include/internal/daemon/config.h:27-29
struct DaemonConfig {
    runtime::MMAgentRuntime::Config runtime_config;
    runtime::master::Deployer::Config deployer_config;    // ← 定义了部署器配置
    runtime::master::Scheduler::Config scheduler_config;   // ← 定义了调度器配置
};
```

`Deployer` 和 `Scheduler` 的配置结构体已定义，但**网络通信层未实现**，Master 和 Worker 只能在本地通信。

## 影响

- 无法水平扩展 Worker 节点
- 所有 workflow 执行集中在单机
- 高负载场景下无法通过增加机器提升吞吐
- 无多节点容错/高可用能力

## 建议方向

| 阶段 | 内容 | 复杂度 |
|------|------|--------|
| 1 | Worker 节点注册/心跳协议（JSON-RPC over TCP） | 中 |
| 2 | Master 远程分发 workflow 给 Worker | 中 |
| 3 | Worker 上报执行状态、结果回传 | 中 |
| 4 | 负载均衡、故障转移 | 高 |
