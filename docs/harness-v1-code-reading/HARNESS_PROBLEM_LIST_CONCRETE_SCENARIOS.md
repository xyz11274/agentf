| 最终响应可能绕过 pending Skill 屏障 | src/agent/agent.cpp:2326-2381、2473-2545；coordinator_decide.py:920-940 | C++ 只在 found_next_skills 分支检查 pending；Coordinator correction loop 会删除 next_skills | 兄弟 Skill 尚未完成时就向客户端发送 final；final 后又出现 Skill completion | 场景：A、B 两个 Skill 中 A 仍在运行，B 完成后触发 Coordinator。模型先错误地重复调度 B，Python 判定重复并删除残留 next_skills，然后在 correction 的下一次 LLM 调用中生成 final。C++ 发现 no next_skills 后直接发送 final，没有检查 pending_skills_count=1。几十秒后 A 完成，又触发一次 Coordinator，形成客户端已经结束但后台仍继续运行和产生日志的轨迹。 |
