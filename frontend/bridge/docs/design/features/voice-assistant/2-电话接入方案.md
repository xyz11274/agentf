## 1. 需求概述

电话接入层负责将 **PSTN（公共交换电话网络）的音频流** 转发到语音 Agent 进程，是语音助手的最底层基础设施。

**核心能力**：
- 接听来电（Inbound Call）
- 拨出电话（Outbound Call）
- 音频流双向实时转发
- 通话状态管理（响铃→接通→挂断）

---

## 2. 方案全景

### 2.1 方案对比

| 方案 | 类型 | 优势 | 劣势 | 推荐场景 |
|------|------|------|------|---------|
| **Twilio** | 云 PSTN | 全球覆盖，API 成熟，WebSocket 支持开箱即用 | 成本较高，国内需特殊通道 | 海外/快速验证 |
| **Asterisk** | 自建 PBX | 完全可控，SIP 协议，支持国内线路 | 运维复杂，需要 SIP 中继 | 国内/自建 |
| **声网 Agora** | 云 RTC | 低延迟，国内优化，对话式 AI 方案 | 绑定平台 | 国内/低延迟 |
| **LiveKit** | 自建 RTC | 可扩展，开源，AI Agent 集成好 | 需要配合 SIP 网关接电话 | 自建/灵活 |

### 2.2 推荐策略

```
Phase 1 (快速验证): Twilio Cloud
  └── 原因: 5 分钟集成，WebSocket 支持完善，无需运维

Phase 2 (国内生产): Asterisk + SIP 中继 或 声网 Agora
  └── 原因: 国内电话号码资源，低延迟，合规可控

Phase 3 (自建/灵活): LiveKit + SIP 网关
  └── 原因: 完全开源，可扩展，与 Pipecat 生态集成最佳
```

## 3. 方案一：Twilio（推荐 Phase 1）

### 3.1 架构

```
Twilio 号码 ← → Twilio Voice API ←WebSocket→ 语音 Agent 进程 ←UDS→ AgentFlow
                    │
                    ▼
              Twilio Media Streams
              (音频流: 8000Hz, μ-law PCM)
```

### 3.2 关键配置

#### 3.2.1 Twilio 号码配置

在 Twilio Console 中为号码配置 Webhook：

```
语音来电 Webhook: POST https://{bridge_host}/api/voice/inbound
```

#### 3.2.2 TwiML 响应（接听来电）

```xml
<?xml version="1.0" encoding="UTF-8"?>
<Response>
  <Connect>
    <Stream url="wss://{bridge_host}/api/voice/media-stream">
      <Parameter name="session_id" value="call_{CallSid}" />
    </Stream>
  </Connect>
</Response>
```

#### 3.2.3 外呼接口

```python
# Bridge 层 API: POST /api/voice/outbound
{
    "to": "+8613800138000",          # 目标号码
    "from": "+14251234567",          # Twilio 号码
    "agent_id": "voice-agent",       # 使用的 Agent
    "workflow_id": "voice-pipeline", # 使用的 Workflow
    "parameters": {
        "task": "order_notification",
        "order_id": "ORD-20260713-001"
    }
}

# Twilio 调用
client = Client(account_sid, auth_token)
call = client.calls.create(
    url="https://{bridge_host}/api/voice/outbound-twiml",
    to="+8613800138000",
    from_="+14251234567",
    status_callback="https://{bridge_host}/api/voice/status",
    status_callback_event=["completed", "answered", "busy", "no-answer", "failed"]
)
```

### 3.3 WebSocket 音频流协议

```
语音 Agent 进程 ← → Twilio Media Streams

Twilio → Agent (上行):
  {
    "event": "media",
    "streamSid": "MZ...",
    "media": {
      "payload": "Base64-encoded μ-law audio"
    }
  }

Agent → Twilio (下行):
  {
    "event": "media",
    "streamSid": "MZ...",
    "media": {
      "payload": "Base64-encoded μ-law audio"
    }
  }

Agent → Twilio (控制):
  {
    "event": "mark",
    "streamSid": "MZ...",
    "mark": {"name": "response-complete"}
  }
```

### 3.4 音频格式转换

```
Twilio 音频流格式:  8000Hz, 8-bit μ-law, 单声道
语音模型输入格式:  16000Hz, 16-bit PCM, 单声道

转换步骤:
  1. μ-law → PCM (G.711 解码)
  2. 8000Hz → 16000Hz (重采样)
  3. 按 20ms 帧 (320 bytes PCM) 切割发送给 ASR/Omni 模型
```

### 3.5 成本估算

| 项目 | 价格 | 一通 5 分钟电话 |
|------|------|----------------|
| Twilio 语音入站 | $0.013/min | $0.065 |
| Twilio 语音出站 | $0.013/min | $0.065 |
| Twilio Media Streams | $0.003/min | $0.015 |
| **电话接入小计** | | **$0.08-0.13/通** |

## 4. 方案二：Asterisk（推荐 Phase 2-国内）

### 4.1 架构

```
PSTN 线路 ←SIP→ Asterisk PBX ←WebSocket/UDP→ 语音 Agent 进程 ←UDS→ AgentFlow
                      │
                      ▼
                ARI (Asterisk REST Interface)
                或 Media Socket (直接音频流)
```

### 4.2 关键配置

#### 4.2.1 Asterisk 配置

```
/etc/asterisk/extensions.conf:
[voice-agent]
exten => _X.,1,Answer()
  same => n,Set(CHANNEL(musicclass)=default)
  same => n,AGI(agi://127.0.0.1:4573/voice-agent)
  same => n,Hangup()

/etc/asterisk/sip.conf:
[general]
context=voice-agent
port=5060
bindaddr=0.0.0.0

[trunk]
type=peer
host=sip.telecom-provider.com
username=...
secret=...
```

#### 4.2.2 音频流方案

Asterisk 有两种方式对接语音 AI：

| 方式 | 说明 | 复杂度 |
|------|------|--------|
| **AGI (Asterisk Gateway Interface)** | 标准 CGI 接口，通过 stdin/stdout 交互 | 简单，但延迟较高 |
| **Media Socket (res_audio_socket)** | 直接通过 WebSocket 传输音频流 | 低延迟，推荐 |

**推荐 Media Socket 方式**：

```
Asterisk 配置:
  /etc/asterisk/media_socket.conf:
  [general]
  enabled=yes
  bindaddr=0.0.0.0
  port=9090

扩展配置:
  [voice-agent]
  exten => _X.,1,Answer()
    same => n,MediaSocket(ws://{agent_host}:{agent_port}/asterisk-media)
    same => n,Hangup()
```

### 4.3 成本估算

| 项目 | 价格 | 一通 5 分钟电话 |
|------|------|----------------|
| SIP 中继线路 | 约 ¥0.03-0.08/min | ¥0.15-0.40 |
| 服务器成本 | 均摊 | ¥0.01 |
| **电话接入小计** | | **¥0.16-0.41/通** |

## 5. 方案三：声网 Agora

### 5.1 架构

```
PSTN ← → 声网 Cloud ←RTC SDK→ 语音 Agent 进程 ←UDS→ AgentFlow
```

### 5.2 关键特性

```python
# 声网对话式 AI 方案
from agora import AgoraRTCClient, ConversationalAIEngine

# 1. 电话呼入 → Agora 分配频道
# 2. Agent 加入频道
client = AgoraRTCClient(app_id, token)
channel = client.join_channel(channel_name)

# 3. 通过 ConversationalAIEngine 处理音频
engine = ConversationalAIEngine(
    channel=channel,
    asr_provider="funasr",    # 内置 ASR
    tts_provider="cosyvoice", # 内置 TTS
    llm_provider="custom",    # 通过 UDS 调用 AgentFlow
)
engine.start()
```

### 5.3 优势

- 国内低延迟（< 200ms RTT）
- 内置对话式 AI 方案，减少自建工程量
- 支持 PSTN 呼入呼出
- 国内合规

## 6. 通话状态管理

### 6.1 状态机

```
          ┌──────────┐
          │  空闲     │
          └────┬─────┘
               │ 来电/外呼请求
               ▼
          ┌──────────┐
          │  响铃中   │◄───────── 外呼重试
          └────┬─────┘
     ┌─────────┼──────────┐
     ▼         ▼          ▼
  用户接听   忙音/无应答   拒接
     │         │          │
     ▼         ▼          ▼
┌──────────┐ ┌──────────┐ ┌──────────┐
│ 通话中    │ │ 记录忙音  │ │ 记录拒接  │
│ (对话轮次) │ └────┬─────┘ └────┬─────┘
└────┬─────┘      │            │
     │ 用户挂断     ▼            ▼
     ▼         ┌──────────┐ ┌──────────┐
┌──────────┐   │ 设置重试  │ │ 结束      │
│ 通话结束  │   │ (定时)   │ │          │
│ (清理)   │   └──────────┘ └──────────┘
└──────────┘
```

### 6.2 Bridge 层的通话管理 API

| 端点 | 方法 | 说明 |
|------|------|------|
| `/api/voice/calls` | POST | 发起外呼 |
| `/api/voice/calls/{call_id}` | GET | 查询通话状态 |
| `/api/voice/calls/{call_id}` | DELETE | 主动挂断 |
| `/api/voice/calls/{call_id}/transcript` | GET | 获取通话转录 |
| `/api/voice/calls/{call_id}/recording` | GET | 获取录音文件 |
| `/api/voice/status` | POST | Twilio/Asterisk 状态回调 |
| `/api/voice/media-stream` | WebSocket | 音频流通道 |

### 6.3 数据模型

```python
# 通话记录 (DataBus 持久化)
{
    "call_id": "CAxxxxxxxxxxx",          # 通话唯一 ID
    "direction": "inbound|outbound",      # 方向
    "from_number": "+8613800138000",      # 主叫号码
    "to_number": "+14251234567",          # 被叫号码
    "status": "ringing|in-progress|completed|busy|failed|no-answer",
    "started_at": "2026-07-13T00:00:00Z",
    "ended_at": "2026-07-13T00:05:00Z",
    "duration_seconds": 300,
    "session_id": "sess-xxxxx",           # AgentFlow Session ID
    "workflow_id": "voice-pipeline",      # 使用的 Workflow
    "recording_url": "/recordings/CAxxx.wav",
    "transcript_url": "/recordings/CAxxx.json",
    "provider": "twilio|asterisk|agora",  # 电话提供商
    "provider_metadata": {                # 提供商特定信息
        "twilio_call_sid": "CA...",
        "twilio_account_sid": "AC..."
    },
    "cost_estimate": 0.12,                # 成本估算
    "tags": ["order_notification", "urgent"]
}
```

## 7. 推荐实施路线

### Phase 1（快速验证）

```
电话接入: Twilio Cloud
对接方式: WebSocket + Twilio Media Streams
音频格式: μ-law 8000Hz → PCM 16000Hz
验证: 一通电话呼入/呼出全链路
时间: 1-2 天
```

### Phase 2（国内生产）

```
电话接入: Asterisk + SIP 中继 或 声网 Agora
对接方式: Media Socket / RTC SDK
音频格式: 按提供商要求
验证: 批量外呼，通话质检
时间: 1-2 周
```

### Phase 3（自建/灵活）

```
电话接入: LiveKit + SIP 网关
对接方式: LiveKit Agents 框架
音频格式: 原生 WebRTC Opus
验证: 全双工，多节点扩展
时间: 按需
```
