> **层级**: L2 · `docs/design/features/voice-assistant/5-场景设计-语音问答.md`
> **状态**: 初稿
> **创建日期**: 2026-07-13

## 1. 场景概述

### 1.1 一句话描述

在现有的聊天界面中，增加**语音通话模式**，用户可以选择"打电话"方式与 AI 对话——**说话代替打字，听代替看，但想打字时随时切回**。

### 1.2 与现有系统关系

```
当前 (文本):
  用户打字 ─→ Bridge(透传) ─→ AgentFlow 工作流 ─→ AI 回复文字 ─→ 前端显示

语音 (新增):
  用户说话 ─→ Bridge(缓冲) ─→ AgentFlow 语音 Workflow ─→ Bridge(透传) ─→ 用户听到
                              │
                              ├── 管线模式: ASR Node → LLM Node → TTS Node
                              └── 全模态模式: Omni Node (Qwen3-Omni 一体化)
```

**核心洞察**：**Bridge 保持薄**——只做 WebSocket 代理和音频缓冲。**语音能力全部在 AgentFlow 侧，以 Python Node 形式运行**。现有 Agent、LLM、MCP 工具、记忆系统**全部复用**。

## 2. 用户场景

### 2.1 场景一：语音通话模式（最简 MVP）

**用户故事**：
> 作为用户，我在穿搭顾问的页面里，点击"语音通话"按钮，进入语音通话模式。界面变成类似电话的样式，我说"今天上海穿什么？"，AI 直接语音回答"上海今天 28°C 多云，建议穿短袖配薄外套……"，全程就像打电话一样，不用打字。

**交互流程**：

```
进入语音通话模式:
  1. 打开穿搭顾问页面（现有界面）
  2. 点击右上角的 📞 按钮
  3. 界面切换到语音通话模式（右侧/全屏）
  4. 显示"已连接"，AI 说"您好，我是穿搭顾问，请问有什么可以帮您的？"
  5. 用户直接说话："今天上海穿什么？"
  6. AI 语音回答："上海今天 28°C 多云，建议穿一件白色短袖..."
  7. 同时左侧文本模式同步显示对话记录
  8. 用户可继续说话，或点击"挂断"退出通话模式
```

**适用 Agent**：任何现有 Agent，零改造

| Agent | 语音场景示例 |
|-------|------------|
| 穿搭顾问 | "今天上海穿什么？" → AI 查天气 + 搭配建议 |
| 知识问答 | "什么是 RTC？" → AI 解释概念 |
| 订单助手 | "我的订单到哪了？" → AI 查订单状态 |
| 闲聊助手 | "讲个笑话" → AI 语音讲笑话 |

### 2.2 场景二：双栏模式（文本+语音同时可见）

**用户故事**：
> 我进入语音通话模式后，左边文本区同步显示对话记录，右边语音区显示通话状态。我可以一边听 AI 说，一边看文字确认，也可以随时在左边打字补充。

**交互流程**（双栏布局）：
```
┌──────────────────────────────────────────────────────────────────┐
│  穿搭顾问                                               📞 挂断  │
├──────────────────────────┬───────────────────────────────────────┤
│  📝 文本对话区            │  📞 语音通话区                        │
│                          │                                       │
│  用户: 今天上海穿什么？    │  已连接 · 00:32                      │
│  AI: 上海今天28°C...      │  🎤 ────▰▰▰▰▰▰── 正在聆听           │
│                          │                                       │
│  用户: 那换黑色呢？        │  🔊 ──▰▰▰▰▰▰▰▰── AI 正在回答        │
│  AI: 当然可以，黑色...    │                                       │
│                          │                                       │
│  [输入框......] [发送]    │  🎤 点击说话  [按住说话]              │
├──────────────────────────┴───────────────────────────────────────┤

└──────────────────────────────────────────────────────────────────┘
```

### 2.3 场景三：仅语音模式（全屏通话）

**用户故事**：
> 我只想专注语音对话，不想看文字。点击"仅语音"模式，界面变成类似手机通话界面，全屏显示通话状态，就像真的在打电话。

**交互流程**：
```
┌──────────────────────────────────────────────────┐
│                                                  │
│              穿搭顾问 · 语音通话                    │
│                                                  │
│              已连接 00:45                         │
│                                                  │
│                                                  │
│                  🎤                              │
│             正在聆听...                           │
│                                                  │
│                                                  │
│            [点击说话] [挂断]                      │
│                                                  │
│  切换到: [双栏模式] [文本模式]                     │
└──────────────────────────────────────────────────┘

用户操作:
  1. 点击"仅语音"进入全屏通话模式
  2. 直接说话，AI 语音回答
  3. 通话记录自动同步到后台，退出后可查看文字版
  4. 点击"挂断"退出，自动回到双栏模式显示完整对话记录
```

### 2.4 场景四：混合交互（语音+文字交替）

**用户故事**：
> 我在语音通话中，突然想上传一张图片让 AI 看。我在左边文本区上传图片、打字，语音区继续播放 AI 的回答。两种模式互不干扰。

**交互流程**：
```
语音区: 用户说"帮我看一下这件衣服"
语音区: AI 回答"好的，请上传图片"
文本区: 用户上传图片 + 打字"这件适合什么场合？"
语音区: AI 语音回答"这件衬衫适合商务场合..."
文本区: 同步显示 AI 的文字回答
```

### 3.2 数据流对比

**管线模式数据流**：
```
用户说话 → 前端麦克风 → WS → Bridge(缓冲) → UDS → AgentFlow
  → ASR Node(音频→文本) → LLM Node(文本→文本) → TTS Node(文本→音频)
  → UDS → Bridge(透传) → WS → 前端播放
  ↑ 所有语音处理在 AgentFlow 内完成                          ↑
```

**全模态模式数据流**：
```
用户说话 → 前端麦克风 → WS → Bridge(缓冲) → UDS → AgentFlow
  → Omni Node(管理 Qwen3-Omni WS 连接, 音频入→音频出)
  → UDS → Bridge(透传) → WS → 前端播放
  ↑ 流式处理在 Node 内部完成                              ↑
```

**文本模式数据流（不变）**：
```
用户打字 → HTTP → Bridge(透传) → AgentFlow LLM Node → 文字回传 → 前端显示
```

### 3.3 各层职责

| 层 | 职责 | 新增代码 |
|----|------|---------|
| **前端** | 麦克风采集、音频播放、三种模式切换、通话状态显示 | WebSocket 客户端 + 通话 UI |
| **Bridge** | WebSocket 代理、音频缓冲、触发 AgentFlow Workflow | `/api/voice/ws` 端点 |
| **AgentFlow** | ASR Node、TTS Node、Omni Node、LLM Node（复用）、MCP（复用） | 3 个 Python Node + 2 个 Workflow DSL |

### 3.4 关键设计决策

**决策一：语音处理放在 Bridge 还是 AgentFlow？**

| 方案 | 说明 | 推荐 |
|------|------|------|
| **AgentFlow Node (选定)** | ASR/TTS/Omni 作为 Python Node 在 AgentFlow 中执行 | ✅ 保持 Bridge 薄 |
| Bridge 内集成 | ASR/TTS 放在 Bridge 层 | 打破 Bridge 定位 |

**选定理由**：
- Bridge 保持薄接口层定位，只做透传和缓冲
- AgentFlow 作为执行器，语音能力以 Node 形式存在，和 LLM Node、MCP 工具**同级**
- 现有 Agent、Session、DataBus、Context 全部复用

**决策二：前端语音采集方式**：

| 方式 | 说明 | 兼容性 |
|------|------|--------|
| **浏览器 getUserMedia** | 标准 Web API，直接获取麦克风音频 | 所有现代浏览器 |
| 移动端原生 SDK | iOS/Android 原生麦克风接口 | 需要 App 集成 |

**选型结论**：先用浏览器 `getUserMedia` + WebSocket，最简最快。

## 4. 交互流程详解

### 4.1 一次语音问答的完整流程

```
时序图:

用户              前端               Bridge (新增语音端点)          AgentFlow (现有)
 │                  │                        │                        │
 │ 1. 点击🎤按钮     │                        │                        │
 │─────────────────→│                        │                        │
 │                  │ 2. getUserMedia 获取麦克风                       │
 │                  │   建立 WebSocket 连接  │                        │
 │                  │───────────────────────→│                        │
 │                  │                        │                        │
 │ 3. 开始说话       │                        │                        │
 │─────────────────→│ 4. 音频帧 (PCM)        │                        │
 │                  │───────────────────────→│                        │
 │  (持续说话)       │    (每 20ms 一帧)      │                        │
 │                  │───────────────────────→│                        │
 │                  │                        │ 5. VAD 检测说话中      │
 │                  │                        │                        │
 │ 6. 停止说话       │                        │                        │
 │─────────────────→│                        │                        │
 │                  │                        │ 7. VAD 检测到静音      │
 │                  │                        │ 8. ASR 转文本          │
 │                  │                        │    "今天上海穿什么？"   │
 │                  │                        │                        │
 │                  │                        │ 9. 调用现有 Chat API   │
 │                  │                        │    POST /api/chat      │
 │                  │                        │    {"text": "今天上海   │
 │                  │                        │     穿什么？"}         │
 │                  │                        │───────────────────────→│
 │                  │                        │                        │
 │                  │                        │ 10. LLM 推理+工具调用  │
 │                  │                        │                        │
 │                  │                        │ 11. 流式返回回复文本    │
 │                  │                        │←───────────────────────│
 │                  │                        │                        │
 │                  │                        │ 12. TTS 合成语音       │
 │                  │ 13. 音频帧流式返回      │                        │
 │                  │←───────────────────────│                        │
 │                  │ 14. 同时返回文字        │                        │
 │                  │←───────────────────────│                        │
 │                  │                        │                        │
 │ 15. 听到 AI 回答  │ 16. <audio> 播放       │                        │
 │←─────────────────│                        │                        │
 │                  │ 17. 聊天框显示文字      │                        │
 │                  │                        │                        │
 │ 18. 可继续说话    │                        │                        │
 │    或切回打字     │                        │                        │
```

### 4.2 关键耗时

| 步骤 | 做什么 | 耗时 |
|------|--------|------|
| VAD 检测 | 检测用户说完（静音 500ms） | 500ms |
| ASR 转文本 | FunASR 流式识别 | 首字 100ms |
| 调用 Chat API | 通过 Bridge 调用 AgentFlow | 1-3s |
| TTS 合成 | 首帧合成 | 200ms |
| 音频传输 | WebSocket 回传 | 实时 |
| **端到端延迟** | **用户说完到听到回复** | **~2-4s** |

### 5.2 三种显示模式

| 模式 | 触发方式 | 布局 | 适用场景 |
|------|---------|------|---------|
| **📝 仅文本** | 默认 / 点击"文本" | 左栏全屏，右栏隐藏 | 传统打字交流 |
| **📞 仅语音** | 点击"通话" | 右栏全屏（类似电话界面），左栏隐藏 | 专注语音对话 |

**模式切换规则**：
- 三种模式**随时可切换**，不中断当前对话
- 切换时保留对话上下文，不丢失
- 默认进入页面时是"仅文本"模式（兼容现有行为）

### 5.5 前端需要实现的功能

| 功能 | 说明 | 实现方式 |
|------|------|---------|
| **三种模式切换** | 文本/语音/双栏，不中断对话 | 状态管理 + CSS 布局切换 |
| **采集麦克风** | 获取用户麦克风音频流 | `navigator.mediaDevices.getUserMedia()` |
| **音频编码** | PCM 16kHz 16bit mono | `AudioContext.createScriptProcessor()` |
| **WebSocket 传输** | 实时发送音频帧 | `WebSocket.send()` |
| **播放音频** | 播放 TTS 返回的音频 | `AudioContext.decodeAudioData()` |
| **通话状态指示** | 聆听/思考/回答状态动画 | 按状态显示不同图标+文字 |
| **通话时长** | 显示已通话时间 | `setInterval` 计时器 |
| **按住说话** | 按住按钮录音，松开停止 | `mousedown`/`mouseup` / `touchstart`/`touchend` |
| **挂断** | 结束通话，关闭 WebSocket | `WebSocket.close()` |
| **同步文本** | 通话内容实时同步到左栏 | 通过 WebSocket 接收文本消息 |

### 5.6 交互模式选择

| 模式 | 说明 | 推荐 |
|------|------|------|
| **按住说话** | 按住 🎤 按钮录音，松开自动发送 | ✅ 双栏/全屏模式主交互 |
| 点击开关 | 点击开始录音，再点击停止 | 辅助交互 |
| 自动 VAD | 检测到说话自动开始，静音自动结束 | 进阶体验 |

**推荐 MVP 用"按住说话"**，实现最简单，用户习惯已养成（类似微信语音）。

## 6. 与现有系统的对接

### 6.1 对接方式

**核心原则**：语音层是**前置处理**，不改变现有的对话接口。

```
现有对话接口 (Bridge Chat API):
  POST /api/chat
  {
    "text": "今天上海穿什么？",     ← 语音识别后填入
    "session_id": "xxx",
    "agent_id": "outfit-stylist"
  }
  → 返回流式文本 (SSE/WebSocket)

语音层的作用:
  用户语音 → [ASR] → 文本 → 调用 POST /api/chat (复用)
  回复文本 → [TTS] → 音频 → WebSocket 推送到前端
```

### 6.2 新增的 Bridge 端点

| 端点 | 方法 | 说明 |
|------|------|------|
| `/api/voice/ws` | WebSocket | 音频流全双工通道 |

**WebSocket 协议**：

```javascript
// 前端 → Bridge (音频帧)
{
  "type": "audio_frame",
  "data": "<base64 PCM 16kHz 16bit mono>"
}

// 前端 → Bridge (控制)
{
  "type": "control",
  "action": "start_speaking" | "stop_speaking" | "cancel"
}

// Bridge → 前端 (TTS 音频)
{
  "type": "audio_response",
  "data": "<base64 PCM 16kHz 16bit mono>",
  "sequence": 1
}

// Bridge → 前端 (文本)
{
  "type": "text_response",
  "text": "上海今天28°C，建议穿..."
}

// Bridge → 前端 (状态)
{
  "type": "status",
  "state": "listening" | "processing" | "speaking" | "idle"
}
```

### 6.3 零改造接入现有 Agent

```
现有 Agent (如穿搭顾问):
  agent.json → 定义 agent_id、skills、tools、memory
  skills/outfit-stylist/SKILL.md → 技能定义
  nodes/llm_call.py → LLM 调用
  nodes/weather.py → 天气查询

对接语音层:
  1. Bridge 新增 WebSocket 语音端点
  2. 语音端点收到音频 → ASR 转文本
  3. 调用 POST /api/chat(复用现有接口) → 传入文本
  4. 获取回复文本 → TTS 合成 → 推回前端
  5. AgentFlow 侧完全无感知 → 以为仍是文本输入
```

## 7. MVP 范围与验收标准

### 7.1 MVP 范围

```
包含:
  ✅ 页面顶部增加模式切换按钮: [📝文本] [📞通话] [📝📞双栏]
  ✅ 文本模式(左栏) — 不变，保留现有输入框
  ✅ 语音通话区(右栏) — 通话状态显示 + 按住说话 + 挂断
  ✅ 仅语音模式(全屏) — 类似电话界面
  ✅ Bridge 新增 WebSocket 语音端点
  ✅ VAD 检测（简化版，直接用松开按钮判定）
  ✅ ASR 转文本（FunASR API）
  ✅ TTS 合成语音（CosyVoice API）
  ✅ 语音通话时，左栏同步显示文字
  ✅ 三种模式随时切换，不中断对话
  ✅ 支持 1 个 Agent（穿搭顾问试点）

不包含:
  ❌ 电话接入 (Twilio/Asterisk/PSTN)
  ❌ 全双工打断（自动 VAD 检测说完）
  ❌ 录音存档
  ❌ 多 Agent 支持
  ❌ 全模态模式 (Qwen3-Omni)
```

### 7.2 验收标准

| 标准 | 目标值 | 测量方式 |
|------|--------|---------|
| 语音识别准确率 | > 90% | 说 10 句话，人工核对转录 |
| 端到端延迟 | < 3s | 松开按钮到听到回答 |
| 语音播放流畅 | 无卡顿/断断续续 | 主观体验 |
| 混合交互 | 语音和文字可在同一会话交替使用 | 测试 |
| 现有功能不受影响 | 纯文字对话功能不变 | 回归测试 |

### 7.3 体验 checklist

```
□ 点击 🎤 按钮，1s 内显示"正在聆听"
□ 按住说话时，音频正常采集
□ 松开后，1s 内显示"正在识别"
□ 3s 内听到 AI 语音回答
□ 同时聊天框显示文字回答
□ 语音回答播放完整，不中断
□ 播放完后可继续说话或打字

```
