# Bridge 配置系统 — 产品需求

> **层级**: L1 · `docs/requirements/prd/config-system-prd.md`
> **状态**: 草案
> **创建日期**: 2026-06-25

---

## 1. What（解决什么问题）

Bridge 配置系统当前存在以下问题：

| 问题 | 表现 | 影响 |
|------|------|------|
| 配置分散 | 配置项定义在 `config.py`，默认值散落在 `Field(default=...)` 中，环境变量名隐式推导 | 无法快速查看"有哪些配置"和"各配置的默认值" |
| 无 .env 模板 | 没有 `.env.example` 文件，用户不知哪些配置可改 | 部署时需读源码才知道怎么配置 |
| 环境变量名不统一 | 部分用 `DAEMON_HOST` 风格，但字段名用了 `daemon_host`（Pydantic 自动转大写），用户需猜 | 易配错变量名 |
| 缺少 Skill Hub 配置 | `skill_hub_dir` 尚未纳入 | 新增功能需先改配置模块 |
| 缺少配置文件说明 | 没有集中文档说明配置项用途、类型、默认值 | 每次改配置都要读代码 |
| 默认值不准确 | `bridge_port` 默认 `8199` 但 docstring 写 `8000` | 文档误导 |

目标：重建配置系统，使其成为**一处可见、处处可用、新增即配**的模块。

## 2. Why（为什么需要）

- **部署友好**: 新用户部署 Bridge 时，一份 `.env.example` 即可完成配置
- **可维护**: 配置项集中定义，环境变量名显式指定，不依赖 Pydantic 自动推导
- **可扩展**: 新增功能（如 Skill Hub）只需在配置类添加一行，即可获得 env 注入
- **可验证**: 配置校验在启动时完成，不合规值立即报错

## 3. 用户角色

| 角色 | 关心内容 | 使用方式 |
|------|----------|----------|
| 开发者 | 所有配置项及其含义 | 阅读 `config.py` + `.env.example` |
| 部署运维 | 网络/存储/日志配置 | 复制 `.env.example` → 修改 → 启动 |
| 功能开发者 | 新增配置项 | 在配置类添加字段 + 更新 `.env.example` |

## 4. In Scope

- 配置类 `BridgeSettings` 的重构（分组、显式别名、校验）
- 新增 Skill Hub 配置项 `skill_hub_dir`
- 创建 `.env.example` 模板文件
- 配置项全量文档（集中一表列出所有 env 变量）

## 5. Out of Scope

- 配置热加载（需重启生效）
- 配置文件层级（仅支持 `.env` 文件 + 环境变量）
- 远程配置中心集成

## 6. 成功指标

| 指标 | 目标值 |
|------|--------|
| 配置可见性 | 一份文档列出所有配置项、类型、默认值、环境变量名 |
| 新增配置 | 添加一个新配置项只需改 1 个文件（config.py） |
| 部署上手 | 复制 `.env.example` → 修改 → 启动，3 步以内 |
