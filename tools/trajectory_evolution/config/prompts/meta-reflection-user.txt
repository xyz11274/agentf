合并采用代表选择：每组增加 canonical_seed_id，必须从本组 seed_ids 中选择一条条件和动作最明确的代表。四个中文文本字段原样复制该代表；程序只累计支持来源，不采用扩大条件或混合动作的改写。触发条件有实质差异、只在部分情形动作相同、或一个要求执行另一个禁止执行时，不能合并。宁可保留独立经验，不把互不相关的两种业务用“或”拼在一起。
顶层 target_type、target_scope（存在时）适用于本请求全部候选，不再逐项重复。合并后原样保留代表的必要条件和例外；只选择语义兼容且直接支持结论的 Seed。
技能编排候选中，明确的 A→B 成功依赖与“失败后不重复委派”“任务完成后直接回复”等一般收敛建议是不同机制，不要合并成一句模糊建议。保留训练证据支持的动作名、先后关系、失败时的依赖分支处理；无依赖的并行请求不得归成串行规则。
输入候选：
{{candidate_json}}
字段约束：seed_ids 是非空字符串数组，最多 256 项；confidence 必须是 0 到 1 之间的 JSON 数字，不是字符串或百分数。四个中文文本字段必须非空，每个不超过 2048 个 UTF-8 字节。不要返回事件 ID 字段（也不要返回空数组）。若末尾带有 validation_error，表示上次响应的相应字段不合规，请按这些约束重新生成，不改变候选来源和证据要求。
只返回一个 JSON 对象：{"candidate_groups":[{"seed_ids":["candidate:..."],"canonical_seed_id":"candidate:...","trigger_pattern":"代表的原始触发条件","observed_problem":"代表的原始问题","proposed_change":"代表的原始修改建议","expected_benefit":"代表的原始预期收益","confidence":0.0}]}。构造每个合并项时，必须先从 allowed_seed_groups 中选定且只选定一项，再从该项的 seed_ids 中原样复制 ID；一个合并项严禁包含两个白名单项的 ID，同一个 Seed 只能使用一次。输出前检查该子集关系；无法确定时就省略该合并项，全部无法确定时返回 {"candidate_groups":[]}。证据由程序从所选 Seed 继承，不输出事件 ID。不得改变证据、创建激活策略或输出上述格式之外的字段。
