# 01 · 概念、目标与整体架构

[文档首页](README.md)

## 本章目标

理解组件和宿主各自负责什么，区分采集、学习、授权和真正执行。

## 设计思路

组件通过任务、模型、动作与循环等执行边界接入宿主。HTTP 和原生入口复用后台算法，分别由常驻服务和宿主实例维护 run。

## 处理链路

处理链路包括以下阶段：

| 阶段 | 输入 | 核心算法或约束 | 输出 | 是否调用模型 |
| --- | --- | --- | --- | --- |
| 采集 | 宿主实际输入、动作、循环决定、结果 | 边界状态机、身份绑定、配对、因果关联 | 标准轨迹 | 否 |
| 校验与分析 | 标准轨迹 | 去重、DAG 校验、Episode 归组、确定性诊断 | 内存中的结构分析报告 | 否 |
| 混合评测 | 结构证据 + 脱敏后的具体内容 | 规则判定、模型语义判断、结论融合 | 单次运行 evaluation | 可选 |
| 候选生成 | 一批 evaluation | 提取建议、证据去重、支持度计算、反证检查 | seeds / candidates | 此阶段本身不新增调用 |
| 元反思 | 同类型、同作用域候选 | 按组语义合并、引用白名单校验 | 更明确的候选 | 可选 |
| 记忆管理 | 候选 + 历史记忆 | 精确匹配、词面短名单、语义关系判断、合并与淘汰 | 持久化 Memory Store | 部分可选 |
| 公共管理 | 合格私人经验 + 可核验独立来源 | 泛化、审查、独立用户计票、跨库关系、争议暂停与过期淘汰 | 可用公共经验投影 | 晋升/语义关系需要模型 |
| 策略准备 | 记忆 + 用户/作用域 + 配置 | 资格过滤、版本指纹、授权、编译 | 本次运行固定的策略快照 | 否 |
| 运行时应用 | 当前请求、动作或循环状态 | 关键词检索、参数约束、状态机 | 增强输入 / Allow-Reject / Continue-Replan-Stop | 否 |
| 回流 | 宿主实际执行观察 | 重新计算决定并核对实际输入/执行情况 | 应用回执进入下一份轨迹 | 否 |

结构分析报告可在内存中处理，后台自动衔接评测、候选生成和记忆管理。
完整任务由后台自动进入评测、候选生成与记忆管理；`auto_evaluate=false` 时不自动执行这条学习链。
`learn` 导入现有日志与在线采集共用 IntegrationService 的评测检查点和按用户入库流程，不再从多个用户的日志直接合成公共库。
独立 `evaluate --no-memory` 仍可用于重新分析，但不会更新学习系统。

主要对象定义如下：

| 对象 | 在当前实现中的含义 |
| --- | --- |
| Run | 一次被采集的任务执行；聊天时可以对应一次用户输入到答复 |
| Activity | 一项模型调用、工具动作或自定义业务活动 |
| Loop / iteration | 宿主明确提供的循环身份和轮次 |
| Episode | 用于分析的执行片段，通常对应一个 step |
| Seed | 从规则诊断或模型反思提取的初始建议 |
| Candidate | 带作用域、条件、行为、证据与质量状态的候选 |
| Memory entry | 持续积累证据、版本和关系的记忆记录 |
| Shadow snapshot | 为一个用户和一次运行筛出的经验快照 |
| Runtime policy | 快照、授权、动作规则、循环规则的固定组合 |
| Application receipt | 宿主是否按决定执行的可核对记录 |

## 选择等级

| 等级 | 宿主需要插入什么                                    | 对 Agent 的影响                                   | run.begin 的 capabilities      |
| ---- | --------------------------------------------------- | ------------------------------------------------- | ------------------------------ |
| L0   | 任务/活动开始和结束的记录                           | 采集、评测、反思、管理记忆，不改变业务执行        | `[]`，可省略                 |
| L1   | L0 + 模型发送前使用增强后的参数，发送后回报实际参数 | 将匹配且获授权的经验加入模型输入                  | `["model"]`                  |
| L2   | L0 + 动作派发前检查决定，逐项回报结果               | 允许或拒绝对应动作，保留原串行/并行调度           | 至少 `["actions"]`        |
| L3   | L0 + 下一轮调度前检查决定，按实际行为回报           | 当前循环 Continue/Replan/Stop，不停止其他循环     | 包含 `loop`，例如 `["model","loop"]` |
| L4   | 后台 GEPA 多轮反思与重组 | 多父谱系、真实任务试验、留出集准入与版本持久化 | 复用已有 L1–L3 打点 |

等级是允许启用的能力上限，各边界独立声明；无工具的 Agent 可以只声明 model/loop。
使用重规划输入需要同时接入 model；运行回执记录各边界实际执行情况。
仅提供任务输入和输出时可使用 L0 的任务结果评测；内部工具、循环与并发分析需要相应活动记录。
L1–L3 必须接到实际发送/执行/调度位置，仅上传历史日志无法控制正在运行的 Agent。

## 证据驱动的记忆更新与受控执行

经验随新证据积累、合并和筛选；通过授权的经验与规则在后续任务的对应边界生效，执行结果再次进入评测。

## 完成状态

| 完成的对象 | 判定依据 |
| --- | --- |
| 业务任务 | 宿主报告真实执行终态和业务结果 |
| 学习批次 | 评测、候选及私人入库阶段有可追踪终态 |
| 策略应用 | 宿主实际使用返回输入/决定，并提供可核验回执 |

公共与私有记忆管理默认启用，经验注入需授权。规则分析可独立运行，公共语义提炼需配置模型。
配置方法见[配置](03-configuration.md)和[公共记忆](14-shared-memory.md)。

## 分层职责与依赖方向

| 层 | 输入 → 输出 |
| --- | --- |
| 宿主边界 | 真实参数与结果 → 标准接口请求 |
| 传输/身份 | C ABI 或 HTTP JSON → 已鉴权操作 |
| 运行状态 | 边界操作 → 事件、活动状态、固定策略 |
| 后台学习 | 完整新轨迹 → 评测、候选、私库 |
| 公共管理 | 合格私库与可核验来源 → 公共投影和跨库关系 |
| 策略编译/应用 | 私人＋公共视图及部署授权 → 有界增强 |

传输、状态存储、模型与算法通过明确接口协作。扩展协议、规则公式、内存布局或控制语义时，
仍需修改实现与测试；仅换模型端点或提示词不需要重新编译。

## 选择部署形态

常驻单进程内的同步或异步 Agent 优先评估原生入口；多短进程需要直接续写同一 run 时使用 HTTP。
如果原生部署有多个工作进程，必须另有常驻所有者接收其事件；本组件没有自动 IPC 转发器。
不需要一个串行总函数，但必须有人负责新任务身份和最终收尾。
