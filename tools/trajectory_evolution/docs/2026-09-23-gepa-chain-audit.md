## 8. 尚未被程序修复证明解决的效果问题

1. **种子质量弱于 L0。** 来源经验可入库、可检索不等于组合注入有益。现有同批 50 题的 32% 对 46% 是实际退化，需要通过搜索中的改写／停用对照验证，不能靠更多注入次数证明改善。
2. **编排提案依赖脆弱的派发形态。** 同名技能两实例的串行规则，在每批只发一次该技能时没有调度作用；长任务原句也不能保证后续轮次仍匹配。这是候选泛化问题，不是把预检总数显示正确就能解决。
3. **浪费出现在干预之前。** 工具末端的失败拦截无法追回之前已经发生的多次 LLM 和重复派发。需要在授权范围内评测更早的派发预算或执行者级循环规则，同时保护后续必要步骤。
4. **部分业务目标与执行条件不一致。** 既有失败报告包括缺少医疗资料仍要求生成、没有实际设备却要求执行成功、技能对测试来源自行拒绝等情形。固定评测环境已经提供并消费初始状态，不是简单漏传 initial_state；不能为提高分数临时编造业务资料、把“未执行”改成“已完成”，或修改留出标准。

因此本次结论是“查明并修复若干确定的链路漏洞”，不是“整个系统已稳定且策略达标”。正常完成候选评测、策略实际介入、同题收益、独立留出通过，是四个不同的验收条件。

### 22.5 L2 终态失败的默认参数身份

`src/gepa/failure_ledger.h` 的 `target_failure_snapshot` 原先在终态规则未声明 `error_scope_arguments` 或声明为空数组时，以空参数对象构造失败身份。同一 execution 中，一个请求失败会使同一 operation 的其他参数也命中终态限制；例如某个地址缺少业务快照，不应同时阻止换地址、换查询或换嵌套参数的可行请求。

本次仅调整上述缺省语义：以完整实际参数的 SHA-256 摘要参与身份，并继续绑定规则、操作、作用域和 execution。不保存参数原文；先取参数摘要，避免合法长提示词或工具参数超过原有 8 KiB 显式字段保护后静默失去规则。包含脱敏占位的参数仍跳过身份生成，避免将不同真实目标合并。明确声明字段（例如 `model`）的配置级作用域保持不变；非终态的普通总次数预算也保持不变。

`tests/test_gepa_evidence.cpp` 的 `terminal_failure_identity` 已覆盖缺省及空数组两种配置、同参限制、不同 action／地址／嵌套参数放行、兄弟 execution 隔离、脱敏参数跳过、显式 `model` 语义和普通预算不变，并增加 12 KiB 参数的同参限制与异参放行断言。原逻辑分别复现“不同参数被同一终态失败污染”和“长参数丢失失败身份”，修复后 `test_gepa_evidence` 完整测试退出 0，相关文件 `git diff --check` 通过。
