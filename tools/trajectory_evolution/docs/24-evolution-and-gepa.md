# 24 · GEPA 多轮搜索、分支重组与完整闭环

[文档首页](README.md)

## 本章目标

连接轨迹采集、记忆管理、后台策略评测与策略应用，配置 GEPA 搜索、理解多父进化谱系，并恢复或离线加载完整策略。

## 设计思路

每个 run 使用固定策略，后台根据新轨迹更新记忆。部署授权控制经验和规则的使用范围，执行回执将应用情况带回下一轮评测。

## 从轨迹到下一次运行

1. 宿主在任务、模型、动作和循环边界上报输入、输出、状态与因果关系。
2. 后台将完整的新轨迹按用户合批，执行规则与模型评测。
3. 从评测中提取候选，按配置进行元反思，更新私有记忆、公共经验和跨库关系。
4. 后台从私有与公共视图编译候选，结合部署授权、动作规则和循环规则形成固定行为版本。
5. 启用 policy_evaluation_file 时，独立实例执行固定任务，与基线比较；通过后登记发布，并更新记忆的实测状态。
6. 新 run 使用缓存中的已发布策略；宿主使用增强输入或控制决定，并提交执行回执。已有 run 保持原版本。
7. 新业务轨迹携带策略和应用信息，进入后续评测与学习；隔离评测试验不进入生产学习队列。

各阶段的状态、版本和产物通过来源引用关联。后台处理频率、批次规模和预算见[学习调度](17-learning-scheduler.md)。

## 授权与运行控制

- 部署配置限定 max_level、用户、scope、动作规则、循环预算和最大注入长度。
- auto_approve_experiences 默认 false。通过 runtime_options.approved_experiences 指定获准使用的 memory_id/content_revision；启用自动授权后，合格经验自动进入候选。启用评测准入时，通过任务测试后才发布。
- 每个 run 固定策略快照；新记忆在后续 run 生效。
- activity.end 回报发送参数、动作执行情况和结果；loop.commit 回报采用的循环决定。
- 宿主保留原有权限、安全检查和业务循环上限。

任务级对照复用 [任务评测模块](19-datasets-and-benchmarks.md)。dataset run 单独输出报告，后台 AgentEvaluationService 进一步处理准入、发布和反馈。未配置 policy_evaluation_file 的部署仍使用原精确授权行为。

## 暂停、恢复与故障处理

离线 `learn --evaluation-only` 接收 SIGTERM 或 Ctrl+C 时唤醒后台等待，并正常回收评测线程、保存 GEPA 取消检查点，退出码分别为 143 和 130。再次运行同一配置会恢复因服务关闭而中断的搜索；已完成成绩继续复用，明确取消后的停机时长不占搜索预算。通过 `agent_evaluation.cancel` 显式取消的作业仍需显式重试，不会因服务重启自行恢复。SIGKILL 或断电无法保存取消时刻，不能据此补回未知的停机时间。

若停止发生在搜索已经落盘、评测结果尚未提交的窗口，恢复时仍复用原作业的完整报告，并补交原库反馈；不会为补交重跑 Agent 或再调用反思模型。只有上下文一致且没有用户显式取消标记的 GEPA 作业自动恢复，普通评测与明确取消保持原规则。

原生模式使用 `evo.set_enabled(False)`，JavaScript 使用 `evo.setEnabled(false)`，控制当前客户端后续边界的增强。

本地开关通过 epoch 区分切换前后的执行。跨越暂停或恢复的 run 被隔离，恢复后的新 run 重新进入增强流程。已发送请求和已发生的业务副作用，继续由宿主及对应业务接口管理。

出现采集缺口时，宿主按原输入、原动作调度和原循环安全限制继续，记录 degraded，并隔离受影响的轨迹。业务结果与采集状态分别上报。

## 回流信息与评测

新轨迹保存 policy_id、decision_id、memory_id、content_revision 和应用回执，用于关联：

- 当时使用的策略和经验版本；
- 实际发送的模型输入、动作执行情况和循环决定；
- 对应任务的结果、时延、调用次数与资源消耗。

轨迹评测分析单次执行过程，任务对照评测比较固定任务集上的版本表现。

## 贯穿全流程的示例

设用户 alice 在 campaign 会话中要求生成宣传图、视频并查询发布信息。三个分支并发执行，最后汇总。

### 第一次运行：采集与分析

视频分支要求参考图，却连续两次提交相同的缺素材参数：

- 两次返回 INPUT_ASSET_MISSING，错误标记为 non_retryable。
- 执行者、执行流、操作名和 loop_id 相同，轮次从 1 到 2。
- 第二次活动通过 caused_by 关联前次失败。

网络查询和图片生成完成，视频分支返回素材缺失。整个 run 正常收尾，业务结果为 partial。

规则将第二次视频请求识别为 non_retryable_repeat。模型基于参数、错误与图片产物生成带条件的经验：

> 视频任务需要参考图且缺少可访问素材时，先引用已有有效图片或补齐素材，再继续生成。独立的查询任务保持执行。

该候选保存 scope、触发条件和直接证据。假设仅有一个 run、一个 Episode 支持，证据置信度为 0.9，按示例公式得到 0.78，状态为 INSUFFICIENT_SUPPORT。它作为待处理记忆保存，等待新增证据。

### 第二次运行：持续入库

同一用户的另一 run 出现同类问题，形成条件和行为等价的建议。候选 ID 相同则直接合并；表达不同则经过规范化匹配或短名单语义判断。

假设积累到两个 run、两个 Episode 的支持且无反证，候选变为 PROPOSED。随后按记忆冲突、作用域、内容契约和版本授权筛选：

1. 存在冲突：保留在记忆库，等待后续处理。
2. 通过筛选但待授权：形成 shadow 建议。
3. 通过筛选且获授权：后续 run 命中条件时进入模型输入。

alice 的私有经验仅用于 alice。跨用户共享通过公共提炼、独立支持与跨库审查完成，详见[公共与私有协作](14-shared-memory.md)。

### 第三次运行：应用与核验

alice 再次提出类似任务，新 run 固定策略。视频相关模型请求命中经验，宿主发送增强后的 input，再用 actual_input 回报，形成 applied 回执。

若部署配置了 video.generate 的必需参数规则，L2 拒绝缺少 reference_image 的动作。网络查询和图片生成继续按原调度执行。

若视频循环持续无进展，L3 按配置执行 replan，并在预算用尽后停止该循环。最终结果重新进入采集与评测。

使用固定任务集比较基线和候选的任务成功率、平均无效 loop、模型调用次数、token 与时延，跟踪优化目标。

## Hermes 思路与本组件的实现

实现参考 [Hermes self-evolution 的技能优化入口](https://github.com/NousResearch/hermes-agent-self-evolution/blob/main/evolution/skills/evolve_skill.py)：冻结初始策略、训练/验证/留出拆分、基于反馈迭代改写、约束校验和最终比较。Hermes 入口使用 DSPy GEPA；本组件用 C++ 实现反思搜索，不要求宿主安装 DSPy 或使用 Python。

父节点选择采用 [GEPA 的逐任务表现前沿思路](https://gepa-ai.github.io/gepa/api/core/optimize/)。这是一套针对本组件受限策略的 GEPA 实现，不是将 Hermes 的代码原样移植：候选是完整 L1–L3 策略，试验复用真实 Agent 执行器与统一评分器，生成内容只改变被授权的策略空间。

L4 是后台优化能力。`max_level`、`instrumentation.level` 和候选的 `level` 仍填写实际需要的 L1、L2 或 L3，不填写 L4。

双亲重组参考 [GEPA MergeProposer](https://github.com/gepa-ai/gepa/blob/main/src/gepa/proposer/merge.py)：选择具有共同祖先的两个不同分支，比较组件变化，再执行真实试验。候选谱系为 DAG；每个节点有一份独立、不可变的完整策略，父版本不会被子版本覆盖。

## 启用 GEPA

前提是已按[任务评测指南](19-datasets-and-benchmarks.md)配置真实宿主命令、评分规则和版本隔离。每个试验由组件启动独立 Agent 实例，使用原有打点采集效果。主 Agent 不等待搜索完成。

1. 复制完整 `config/` 目录到部署目录；保持 `runtime.json` 与它引用的 `prompts/` 相对位置。
2. 在任务集准备非空的 `train`、`val`、`holdout`，全部完成 review；同一任务族/会话保持在同一 split。
3. 在 `runtime.json` 配置自己的反思模型、endpoint、`api_key_env`、thinking 和请求超时。凭据只放环境变量。`gepa.json.runtime_config` 可指向与其他后台模块相同的配置。
4. 在既有 `agent-evaluation.json` 增加：

   ```json
   "gepa_config": "gepa.json"
   ```
5. 服务配置继续使用 `"policy_evaluation_file": "agent-evaluation.json"`。允许的经验通过 `auto_approve_experiences` 或 `runtime_options.approved_experiences` 进入候选。
6. 启动组件。后台先检查当前用户与公共库合并后的可用经验。不足时自动执行训练任务、采集和学习；足够后提交 L1–L3 种子进入 GEPA。也可使用既有 `agent_evaluation.submit` 提交已准备好的冻结候选。

留出任务数 × repetitions 至少满足 `gate.min_trials`。修改配置或提示词不需要重新编译；重启组件建立新实验上下文，避免在同一棵树中混用不同配置的成绩。

省略 `gepa_config` 就保持原评测行为。这里不需要新的宿主 hook、observer、适配器或打点。

## 经验不足时自动补充训练

此机制不限于首次启动或空库。后台先按既有编译规则处理用户私有经验与公共经验的重复、冲突、归档状态、作用域和授权，再统计最终策略中实际存在且已批准的经验。数据库总行数、历史版本数和已经失效的批准记录都不计入。

在 `agent-evaluation.json` 配置：

```json
"training": {
  "enabled": true,
  "min_experiences": 3,
  "batch_size": 16,
  "max_batches": 4
}
```

以上也是省略参数时的默认值；各数量范围为 1–512。`min_experiences` 是可配置的数据准备门槛，不是任务成功率指标。最终策略仍要接受独立的真实执行评测和发布门禁。

| 当前情况                                        | 后台行为                                                                                 |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 没有经验，或过滤与授权后不足`min_experiences` | 用原 Agent 的 L0 无策略版本执行下一批已审核训练题                                        |
| 经验很多，但无法进入当前策略                    | 按实际可用经验数判断，不用存储总数跳过训练                                               |
| 本批轨迹正在分析或入库                          | 等待既有学习队列完成，不同时启动下一批                                                   |
| 本批学习完成但仍不足                            | 在预算内选择未使用的训练题，再补充一批                                                   |
| 已满足门槛                                      | 停止补充训练，编译种子并进入 GEPA                                                        |
| 训练执行、入库或学习发生错误                    | 保留具体阶段状态，不自动无限重试                                                         |
| 批次数用尽或训练题耗尽，经验仍不足              | 记录`budget_exhausted` 或 `training_exhausted`，保留已生成的经验自动学习需要服务配置 |

`auto_evaluate=true`

。通常配合

`auto_approve_experiences=true`，使质量与隐私门禁通过的经验可以成为待评测候选；它不会绕过策略发布评测。使用手工批准列表时，只统计其中仍然匹配内容版本的经验。缺少目标级别的打点能力或批准权限需要修正配置，训练不会扩大宿主权限。每批复用已配置的原程序启动命令、入口绑定、打点采集、超时、隔离进程、并发和每小时评测限额。主 Agent 不等待训练。训练量额外受 `batch_size × max_batches` 限制；`repetitions` 决定每题实际执行次数，多轮题继续按原评测器收集多个 Run。

### 数据入库边界

自动训练复用任务执行器但跳过任务裁判；GEPA、基线与留出评分配置不变。
任务评分不是经验入库的前置步骤。执行后的轨迹模型分析与元反思独立读取学习运行配置，
默认开启，也可分别关闭。只运行规则时，仍保存有证据支持的候选；无可提炼候选则如实为空。

1. 仅选取冻结数据集里 `split=train` 且 `review_status=reviewed` 的题目；验证集和留出集不进入经验库。
2. 原 Agent 以明确的 L0、空策略版本执行。校验报告完成标记和指纹、数据集与题目版本，以及每条真实轨迹的用户、应用、版本、试验 ID 和闭合完整性。
3. 有可信完整轨迹的成功、业务失败，以及明确未请求任务评分的训练样本都可以学习；未评分保留 `uncertain`，不改成成功。裁判异常、执行状态不明、截断或缺失轨迹不能使用未评分路径。已有隐私检查保持生效。
4. 通过校验的轨迹进入原来的分析、元反思与记忆管理队列。Run 清单保留 `training_source`，原轨迹中的评测 ID 不删除。直接从普通日志入口导入评测轨迹仍被拒绝。
5. 训练身份用于该用户的私有种子经验，不作为独立真实用户为公共经验投票。训练可以按冻结数据集中的独立题组支持公共经验；导入自动登记来源，无需先启动 GEPA 或任务裁判。公共库的提炼、复核、去重、冲突和淘汰门禁保持不变。

导入后的轨迹副本在 `attributes.training_evaluation` 保存离线验收上下文：`expected_behavior`、`constraints`、
试验 `verdict`、`checks` 和整场试验的 `run_ids`。原始报告与执行事件不变；这些字段不是新增执行结果，
而是后续分析、反思判断必需动作是否完成的参考。多轮试验的总体结论不直接套用于其中每个 Run。
例如解析命令被拦截，之后仅写入和读回 JSON 文件，不能当成已经实际运行解析器。
上下文经过相同隐私与大小检查；普通会话不需要提供这些字段。已经导入的旧轨迹不会被回填或重复分析。
未请求评分且整题结论未知时，另保存 `task_assessment_status=not_requested`，供后续分析区分
“没有做任务评分”和“已判定业务失败”。元反思关闭、跳过或响应无效不会丢弃已有规则候选。

### 重启、去重与查看状态

进度和已经使用的题目版本记录在组件现有 `agent-evaluation/state.json`，不按记忆 revision 重置训练预算。相同应用版本和数据集版本在重启后继续使用该进度；已完成的报告导入也是幂等的。执行中被中断的训练保留 `interrupted`，不会擅自再调用宿主。

使用既有 `agent_evaluation.status`，查看返回的 `training`：

| 字段                                         | 含义                                                                                          |
| -------------------------------------------- | --------------------------------------------------------------------------------------------- |
| `status`                                   | `training`、`ready_to_import`、`waiting_for_learning`、`ready`，或明确的失败/耗尽原因 |
| `usable_experiences` / `min_experiences` | 当前真正可用于种子的经验数 / 准备门槛                                                         |
| `batches`                                  | 已经分配的补充训练批次数                                                                      |
| `tasks`                                    | 本次应用版本和数据集下已使用的题目版本，用于避免重复分配                                      |
| `job_id` / `run_ids`                     | 当前训练作业 / 该批已接收入学习队列的真实 Run                                                 |
| `identity`                                 | 应用版本与冻结数据集的进度标识，不包含记忆计数                                                |

对应的作业带 `training=true`，不会充当发布成绩，也不会生成生产策略发布记录。后台学习失败显示 `learning_failed`；报告无法入库显示 `import_failed`。已有 `agent_evaluation.retry` 可显式重试执行失败/中断的训练作业；更换训练集或应用版本会建立新的数据准备进度。

修改评测配置后重启服务，尚未完成且未主动取消的当前训练批次会在新配置下重新排队：保留原任务清单和批次预算，使用新的作业目录，不复用旧配置的检查点。新作业的 `supersedes` 指向旧作业，旧报告保留可追溯。已完成批次不重跑；同一配置下的失败以及主动取消仍需显式处理，不会自动无限重试。

离线执行可使用 `trajectory_evolution learn --config SERVICE_JSON`：无需预先有用户会话，组件在配置了 GEPA 与自动学习时完成补充训练、学习和后续策略评测。命令等待后台队列，不因暂时没有待学习日志而提前退出；经验仍不足或学习失败会以非零退出码报告。省略输入时不会清空已有记忆。

## 一次搜索的完整算法

1. **冻结实验上下文。** 保存当前生产基线和记忆编译得到的 seed。上下文绑定任务集版本、宿主 revision、评测配置、反思配置/提示词和控制授权。当前生产基线尚未发布时使用 L0。
2. **评测树根。** 在验证集执行 seed，保存逐题质量与成本。缺乏有效评分或循环证据时停止；未知 token 默认拒绝，也可显式使用下文的保守成本策略，不能把未知用量计成零。
3. **选择父节点或重组分支。** 默认保留逐题最优节点，移除前沿覆盖被更优候选包含的冗余节点，按占据前沿的频次抽样。内部节点和叶节点采用相同资格规则。已有新候选且存在合适双亲时优先尝试重组。
4. **抽取训练小批次与组件。** 默认按 epoch 重新洗牌，末批可短于 minibatch_size，不重复填充题目。父子使用相同任务与 repetitions；全树共享轮换游标，动作、经验、循环组件交错安排，分支不会重置进度。已发现某控制组件的可执行训练机会时，为它保留一个对应样本，其余继续按 epoch 抽样。可以配置同父多个提案、独立采样或 P×N 采样。
5. **生成反思改写。** 模型只接收本轮获选组件当前值、合法来源和有预算限制的训练反馈；L1 根据实际应用回执优先选择用过获选经验的样本，L2/L3 优先选择与控制条件相关的证据，然后才按失败及低收益排序。控制反馈的 16 项窗口优先保留已有结算轮次的上层重复派发检查点，避免被一个子分支的大量重试挤掉，输出仍按原始顺序排列。新发现且尚未探索的控制机会优先得到一次反思，经验则优先修改训练中实际注入的条目。验证与留出任务正文不进入反思。可选满分跳过检查实际质量和 fitness，而非仅检查业务成功。
6. **建立子节点。** 反思节点记录一个父节点；重组节点记录两个父节点、共同祖先、组件来源和冲突。所有候选都经过隐私、来源、范围、长度和控制边界检查，再编译完整策略。相同行为版本记为 duplicate，跳过额外试跑。
7. **小批次筛选。** 反思候选默认要求严格改善，先保质量再看 fitness；可配置不退化接纳，或 acceptance=pareto 保留局部优势。同批提案可全部保留通过筛选者，或按相对各自父版本的平均质量增益、fitness 增益选最佳／Top-K。不同提案的批大小可能不同，使用均值增益比较。
8. **验证并更新前沿。** 被选中的反思提案执行验证。开启评测缓存时，训练中尚无实际应用回执的新控制规则先探测至多 `minibatch_size` 道验证题；同一规则在训练和探测中均有查询机会却始终零应用，则标记 `unobserved_controls`，结束该候选，不再消耗剩余验证题。训练未命中而验证已命中的规则继续完整验证，探测题从缓存复用。没有查询机会不按此规则提前结束；关闭缓存时保持完整验证。重组候选先在覆盖双方优势与平分任务的验证子集上比较，按下述严格或 Pareto 筛选进入完整验证。同版本、同 split、同上下文的已完成逐题记录复用，只补跑缺题。
9. **停止搜索。** 达到轮数、模型调用数、试验预算、耐心或总时间边界。试验预算预留最终留出集的基线＋候选成本；预算不足不会再启动一个无法负担的试验。
10. **最终验收。** 先固定 winner 并检查其验证目标；未达标时搜索状态为 `validation_rejected`，作业正常返回 `rejected`，`gate.stage=validation`，不启动留出集、不生成留出报告、不导出选中版本。验证合格后才在留出集比较生产基线与 winner，使用原来的质量、覆盖率、配对样本、时延、token、无效循环准入规则。留出失败就保留原生产版本，不把失败详情反馈给反思模型后继续针对同一留出集搜索。
11. **发布。** 只有该用户/等级的任务仍是最新候选、生产父版本未改变且准入通过，才登记新版本。新 run 从缓存取用；已开始的 run 保持原版本。

逐题补测会检查同一上下文中已结束批次的有效题目，包括当前批次的上一次尝试：即使该批次另有题目评分出错，已完整评分且具备
当前目标所需指标的题目仍可复用，包括正常判定的业务失败。每题必须保留全部 repetitions；error、uncertain、
缺失循环指标、未完成评分或默认策略下缺失 token 的记录不充当有效成绩。报告哈希、版本、split 及上下文绑定仍须通过校验，
不从最终留出对照提取记录用于搜索；`cache_evaluations=false` 仍完整重测。

反思输入受题数和字节预算限制。选择训练反馈时先保留失败题，再按既有目标函数的 fitness 从低到高选择；因此任务虽然通过，但包含较多无效轮次或较高调用成本，也有机会优先进入反思，不再仅按题目顺序截取前几条。L2 的数据集依赖提示和“先／再”等文字线索仅用于相关样本之间排序，不据此删除其他已采集的编排证据；没有这些词并不等于没有依赖，也不能让一个误命中的独立任务排除整批样本。
L1 经验反思可查看精简后的模型输出；L2/L3 控制反思只保留所选边界的执行证据，不重复发送模型请求和响应信封。`actions[].action_control` 只在存在匹配 action_id 的真实动作策略查询时提供查询事件 ID、scope、可用的 schema 必填参数与控制决定；否则为 null。模型输出中的 tool_calls 是计划，不能据此推断动作控制已获得介入机会。宿主在打点前拒绝的调用不应被描述为新增 L2 拦截收益；事后拦截也不能消除已经发生的模型轮次。这些字段只来自训练执行证据，不扩展动作授权，也不改变原始日志。
`loop.decision` 的 `loop_control` 通过同一轨迹内的控制步骤关联实际循环查询。`observed_no_progress` 保留规则判定前的计数：取连续状态不变次数与连续仅重复已有动作输入／输出的步骤数之较大值，包括 replan 清零前的值；`proposed_decision` 与外层宿主实际 `decision` 分开保存。没有查询、未更新计数或有在途动作时不推断计数。反思只使用这项运行时证据判断无进展阈值是否可能命中，离线评审的 waste 仍用于效果评价，两者不能互相替代；不额外发送状态全文或指纹字符串。
L3 反思会额外保留压缩后的评审 `loop_review`，并按轨迹中的实际先后顺序排列所选循环事件；L2 编排／动作反馈不携带该评审字段，以免挤占执行证据预算。
缓存命中还会核验当前目标需要的指标；历史索引中的 `complete` 不会让缺少 token 或循环指标的种子报告永久卡住。
补测结果仍不确定时，报告的 `complete` 保留“本批执行已结束”的含义，缓存标记为 `inconclusive`，下次只补测未获有效成绩的题目。
拼接报告的 `source_report_refs` 记录来源缓存键、具体 attempt 报告路径和哈希；同一缓存键的重试指向旧报告，便于追溯复用来源。

### 实际应用证据

`control_coverage.rules` 分别记录 L1 改写经验、L2 技能编排、参数护栏和 L3 循环规则，`boundary` 分别为 `llm`、`schedule`、`actions`、`loop`。三个计数有不同含义：

| 字段 | 含义 |
| --- | --- |
| `queries` | 对应作用范围内实际发生的策略查询次数 |
| `triggered` | 查询选择了该改写经验，或规则提出了动作拒绝、循环 replan/stop |
| `applied` | 查询与实际执行回执的策略、查询、决定和经验来源均匹配，确认改写进入模型请求或控制已执行 |

L1 改写的覆盖标识由完整改写内容及来源计算；文本变化后不能沿用旧文本的注入证据。保留原文的经验不增加改写覆盖项，主动禁用经验也不要求注入回执。生成的控制规则继续使用其内容标识。搜索中缺少新改动真实应用的候选标记为 `unobserved_controls`，未改动的继承规则不阻挡新改动继续搜索。最终发布默认按效果门槛验收；只有显式严格覆盖模式才使用 `generated_control_not_observed`，也适用于未被实际注入的 L1 改写。

完整验证保留本候选训练阶段已取得的应用证据，并可继承任一父节点中内容相同的规则证据。不要求一条场景规则在每道题或每个数据划分中都命中；训练中命中、验证中未遇到对应场景时，应用证据仍有效。训练、验证的查询计数在提前淘汰判定时分别检查，避免把训练查询当成验证机会。生效覆盖只证明策略被执行，质量、时延和无效循环收益仍须独立通过验证与留出对照。

`control_coverage.rules` 和 `complete` 检查当前生成规则／经验改写是否被使用；空规则集合只表示没有待核验规则，不表示各级能力都已生效。
`capabilities` 分别统计 `llm`、`actions`、`schedule`、`loop` 的 `queries`、`triggered`、`applied` 及 `required`。`level_complete` 与 `unobserved_capabilities` 检查本级已声明能力：L1 核验实际请求注入；L2 已声明 schedule 时必须有真实技能编排，否则核验动作控制；L3 另须有实际 replan 或 stop。仅查询、始终 continue、计划和派发 ACK 都不计实际应用。

GEPA 与固定候选评测默认 `gate.require_level_coverage=false`。选优先比较效果约束是否满足，再比较目标得分、逐题稳健性与评测收益；技能编排未触发或存在未使用的继承规则，不会让高覆盖但退化的版本压过效果更好的版本。最终发布仍须满足通过率、评分覆盖率、无效 loop 和时延等已配置门槛，能力覆盖只作诊断。

如需专门验收全级能力，可显式设置 `gate.require_level_coverage=true`，此时选优还要求生成规则与等级覆盖完整，发布会使用 `generated_control_not_observed`／`level_capability_not_observed` 拒绝缺证据的候选。覆盖要求不抵消质量退化，也不要求每道题触发所有能力。搜索阶段可以累计相同规则的应用证据；严格模式的最终全级别验收使用本次最终评测中的实际回执，不用训练或父节点历史计数代替当前能力证明。

`accepted` 表示候选已有有效验证成绩且现有生成规则应用覆盖完整；局部改进仍可保留并参与多父融合，不要求每个中间节点独立覆盖全部级别。最终选优考虑全级别生效覆盖，`winner` 表示验证阶段选中；是否生产生效以 `decision.json.published` 为准。
反思变异和双亲重组共用一个谱系，不使用 MCTS 的 UCT 或随机 rollout。节点与边来自实际候选生成和真实试验。

## 双亲如何一起生成后代

例如共同祖先 O 有经验 E0 与编排 S0。A 将经验改为 E1，B 将编排改为 S1。重组可生成同时包含 E1、S1 的 C，并记录 parents=[A,B]。

| 组件                | 祖先 O | 分支 A | 分支 B | 重组 C     |
| ------------------- | ------ | ------ | ------ | ---------- |
| experience:memory-a | E0     | E1     | E0     | E1，来源 A |
| action_rules        | S0     | S0     | S1     | S1，来源 B |
| loop_rules          | L0     | L0     | L0     | L0         |

A 即使已有其他子节点，也可和叶节点 B 重组。筛选依据是前沿表现，而不是节点是否位于最深一层。

重组规则：

1. 两个候选必须来自同一冻结实验的有效前沿，具有共同祖先，彼此不是祖先与后代；每个分支至少在一个验证任务上优于祖先。分支可以平均成绩较低，但在不同任务上各有优势。
2. 优先使用较深的共同祖先，固定 seed 使分支抽样可复现。同一双亲／祖先组合只尝试一次。
3. 某组件只有一方改变时采用该方；双方相同时保留共同值；双方改变且内容不同时，优先采用验证质量／fitness 更好一方，平分稳定选择第一方。
4. 至少两个差异组件实际来自不同分支才形成有效重组。仅一条经验且没有其他可变组件时，重组通常不会产生新组合，记录 skipped_merge。
5. 经验按 memory_id 分组件，正文、版本内触发条件与可选操作证据约束一起继承或融合；生成 schedule_rules、action_rules 与 loop_rules 各作为一组，保持组内规则顺序。不修改手工规则、授权、来源 revision、scope 或底座代码。
6. 重组本身不调用反思模型。重新编译后再校验组合授权和总规则数，并重新评测；任何检查失败均保留原父版本。
7. 默认要求子集 quality、fitness 均不低于任一双亲，且原始无效 loop 均值不升，才进入完整验证。acceptance=pareto 时，相对每一位父节点“不退化”或“至少一题有局部优势”即可继续验证；分支相对共同祖先的资格也按同一局部优势规则判断。最终发布仍独立经过 holdout 准入。

为同一个父版本尝试多个方向，并为重组留出节点预算，可在 gepa.json 中设置：

```json
{
  "use_merge": true,
  "max_rounds": 16,
  "max_model_calls": 8,
  "max_merge_invocations": 5,
  "sampling_strategy": "same_parent",
  "proposals_per_round": 2,
  "component_selector": "all",
  "proposal_selection": "all_improvements"
}
```

以上是需要合入既有配置的字段，不是独立的完整配置文件。允许合并不表示每轮强制合并；没有互补分支时继续反思。达到反思调用数上限后，剩余节点、试验和时间预算仍可用于重组。

## 可优化内容与记忆的关系

| 改写类型    | 生效方式                                                                                   | 保持不变的边界                                         |
| ----------- | ------------------------------------------------------------------------------------------ | ------------------------------------------------------ |
| 经验及适用条件 | `RuntimeOptions.experience_overrides` 按来源 `memory_id/content_revision` 保存正文、可选 `trigger_pattern` 和 `observed_operations` | 来源记忆、scope、授权及私有/公共冲突筛选不变；新条件随版本保存 |
| L2 技能编排 | `schedule_rules` 选择现有技能之间的 A→B、B→A 或恢复无新增依赖的并行计划；新规则带任务包含/排除条件 | 只作用于实际批次，保留宿主硬依赖；不创建新动作，不改业务参数 |
| L2 固定契约 | 自动使用当前分支实际模型请求的工具定义检查必填参数是否存在；不是可变搜索维度 | 不把可选字段升级为必填，不从自然语言推断权限 |
| L2 通用生成规则 | `schema_required_nonempty` 将运行时 schema 的必填参数约束为存在且非空 | 仅有真实动作边界证据时尝试，不重复宿主已有拒绝 |
| L2 显式扩展规则 | 兼容已有 control_learning.actions 授权，生成附来源的参数规则 | 属于可选高级配置；普通接入不需要填写工具清单 |
| L3 生成规则 | 收紧连续无进展或恢复预算；有完整浪费尾部证据时在授权范围内调整分支轮数上限 | 保留必要工作与收尾，不放松基础限制，不影响并发兄弟分支 |

随包配置使用 `component_selector=round_robin`，按全树共享游标交错安排经验、动作与循环组件。新发现且尚未尝试的可执行控制机会优先获得一次生成机会；缺少证据时暂缓该控制组件，优先改写本批次确实注入过的经验。`all` 与 `model_choice` 可显式选择，允许模型从全部授权组件中选择改动。没有可靠依据可返回空 experiences 数组，按重复版本处理，不额外执行 Agent。组件越权、格式错误或泄露测试值均记录固定错误码。

反思正文和适用条件读取当前父版本，不读回种子旧值；冻结种子仍限定可修改的来源身份。`components` 仅含本次允许修改的组件，其余 `experiences` 与 `controls.control_sources` 只提供只读依据，不能据此改写未获选经验。

默认外置模板使用 `<!-- gepa:experience -->`、`<!-- gepa:schedule_rules -->`、`<!-- gepa:action_rules -->`、`<!-- gepa:loop_rules -->` 分节；`common` 总是保留，`controls` 在任一控制组件获选时保留，逗号分隔的多个类别按任一获选保留。标记作用到下一标记之前，运行时仅加载相关内容。未使用这些标记的自定义纯文本模板原样读取，不要求用户迁移配置。反思与 COMBEE 汇总都遵守同一选择，联合组件不会丢失任一类说明。

单独编排反思保留批次实例、资源参数和完整依赖，移除无关的动作计数、循环条件和逐轮评语；较长工具内容只保留带截断标记的背景预览，不能拿它推断缺参。原始日志、评分输入和联合动作/循环的类型化证据不变。

模型误改获选组件之外的经验时，无论是已有 ID 的组件越权还是只读来源 ID 不属于 L1 组件，均在已有次数、模型调用和输入预算内至多修正一次。修正请求复用一条训练反馈，不传回越权草稿、不重新执行 Agent；修正后仍走完整权限验证，持续错误不放行。

反思和分组汇总默认使用 `control_updates` 增量修改，避免新增一个执行者的规则时遗漏其他执行者的旧规则。每项包含 `component`、`op`，以及按操作需要的 `index`、`value`：`add` 追加完整规则；`set` 替换指定规则；`remove` 明确删除指定规则。`index` 始终是本次父策略组件数组的 0 基下标，删除前一项不会改变后续索引；同一旧条目不能重复修改。未提及规则保持原样，基础规则不参与这些编辑。空数组为无改动，越界、混用、未授权组件均拒绝。规范化后继续走既有控制编译、预检、真实评测与发布门禁。

旧 `controls` 草稿仍表示该类别完整生成规则的替换，以兼容已有调用；不能与 `control_updates` 同时使用。该增量格式仅用于生成阶段，导出策略仍保存完整规则，不改变运行时或宿主接入协议。

新的 `repeat_failed_operation` 提案必须给出轨迹中真实的 `operation`，不能省略或填写 `*`；运行时只拦截该操作，不把某工具的失败扩散到其他工具。已有通配规则仍可加载、原样继承或移除。缺少操作名时，在已有模型调用预算内至多纠正一次；仍错误就拒绝，不执行该候选。显式操作范围在编译、父组件重建和版本保存中保持一致。

`control_preflight.rules` 保留预检总命中次数，同时提供 `planning_hints`（模型规划提示变化）与 `execution_changes`（依赖、动作或循环决定的回放变化）。提示命中可让候选进入探索，但不是已执行技能编排；两者都不是实际应用次数，实际应用继续读取 `control_coverage` 中经过运行回执确认的 `applied`。

对于有真实重复派发证据的操作预算、或有完整浪费尾部评审的循环上限，反思请求还可提供 `controls.editable_bindings`。模型通过 `control_binding_updates` 选择本次 `binding_id`、同作用域的 `memory_id`、预算值和理由，程序还原确切操作或执行者。新规则追加；同对象、同作用域唯一旧规则则只修改预算，保留其他条件；歧义、越界和跨请求绑定拒绝。操作预算不得超过已观察落定轮数，循环上限必须在授权范围内且小于实际观察轮次。最高必要轮次只是供模型判断质量风险的证据，不是新的授权。

最多提供 6 个绑定，只占原请求预算剩余空间，动作与循环交替保留机会。ID 绑定本次反馈、组件和阶段，COMBEE 分组各自解析，汇总仍使用既有具体规则。单份草稿不能混用绑定和具体增量格式；其他原语、显式删除及旧格式继续可用。绑定错误在原调用预算内最多纠正一次，不执行新的 Agent 任务；通过绑定校验仍须差分预检、真实执行回执、质量与成本评测，不能直接发布。

每次反思另记录固定诊断：`transport_ok`、`error_code`、`attempts`、`duration_ms`、`decoded_body_bytes`。只记录允许的固定错误码或有界数字码，不把响应正文、地址、凭据或自由异常文本写入该诊断。

操作预算的 typed binding 优先完整训练评审中的较早冗余后缀，标记为 `reviewed_redundant_suffix`。识别在展示裁剪前完成：后续必要步骤、缺失评审、同计数的必要并发调用都会阻止该标记；不同 Run 不拼接计数。旧 `observed_bindings` 仍保留最大观察计数。该标记是候选机会，是否能泛化仍由真实 Agent 评测决定。

经验停用只作用于 L1 文本注入。策略通过版本绑定的 `disabled_injections` 记录停用来源，保留已批准来源供独立 L2/L3 规则使用；恢复同一经验可重新注入，不删除 memory。私有/公共重复经验按同一组件处理，避免停用后从公共副本重新注入。

归并只使用已校验的 duplicate 关系：私有关系版本、公共发布内容版本，以及双方实际 ShadowExperience 批准版本分别核对，不把两种 revision hash 直接比较。合法公共回执归到对应私有搜索项，独立公共经验仍保留自己的搜索项；关系过期、内容变化或未批准时不借用另一条经验的应用证据。L1 的停用/恢复/条件收窄不删除公共经验作为 L2/L3 的批准来源。

自动消融使用训练轨迹中已验证的注入回执：当前选中经验确实注入，且该题失败或存在完整评审确认的浪费时，安排一次停用对照。共现不是有害归因，仍须真实评测决定是否保留。`same_parent` 在同批次第二提案安排消融；`independent` 不依赖同批次兄弟节点，同一父版本、同一经验最多自动安排一次，后续继续模型改写。检查点保存并恢复该去重记录，不以父节点编号代替父版本。

L3 规则可带 `error_codes` 和 `after_action_rejection`。前者匹配当前分支已结算的精确结构化故障码（列表内 OR），后者要求该步已验证的 L2 拒绝；同时配置则两者必须成立。成功进展抑制陈旧条件，pending 保护保持有效；不匹配时使用基础循环规则。新候选减少重规划预算必须说明可执行条件，`reason` 只作说明，不参与匹配。既有未配置条件的策略仍按原语义运行。

训练筛选除比较评分，还对照父策略回放实际边界，检查策略是否确实改变注入、动作、编排或循环决定。无行为差异的候选记为 `unobserved_changes`，不继续消耗完整验证预算；真实经验停用和控制删除也可通过差分回放证明发生了变化。查询次数、规则 ID 变化或随机的更短执行不能代替这一证据。

训练筛选还在这些真实差分题目上复用当前 acceptance 判定：无改动题目的随机改善不能掩盖实际干预题目的退化。Pareto 模式继续保留有真实局部收益的分支，允许持平的配置仍允许持平；不满足时记录 `no_observed_training_gain`，无需继续验证。恢复旧 screened 检查点时也会复核已有证据，原始评分不变。有真实注入回执的 L1 探索轮次不被尚未探索的控制类别抢占；未应用的经验仍可让位，控制类别保留各自的轮转入口。

支持安全收尾的边界可提供 `can_finalize`：由当前打点的 `finalize_on_stop` 和包内已加载的收尾模板共同确认。`require_finalization=true` 的 L3 规则只在此能力存在时生效，缺失则回退基础规则。GEPA 在完整评审与原始轨迹证明“连续浪费后仅剩一次无工具最终答复”时，可以探索保留最终答复的提前收尾预算；仍保留配置的最低轮数，不把最后答复当作浪费。未知输出格式、缺失结束事件、后续必要工具工作或不支持收尾均不启用这一机会。旧日志缺少能力字段时不推断支持，需后续真实运行采集该证据。

模型合法返回但没有实质改动时，程序可从当前授权的训练证据中补一个受限控制候选：L2 采用已完整评审的冗余派发后缀预算；L3 采用上述必须安全收尾的迭代预算。来源只能关联已有同操作/执行者规则，或同一执行实例、同一轮中真实交给模型的已批准经验；同 scope 的任意经验不够。该候选是训练评审提出的假设，不宣称记忆正文已经得出相同结论。

此路径不覆盖模型的有效提案，不增加反思模型调用，继续经过既有绑定校验、预检、真实训练、行为归因与发布验收。`generation_method=reviewed_control_probe` 及 `control_probe` 保存假设来源、证据引用、经验关联和状态，原模型草稿保留；按父版本和可执行控制内容去重，检查点恢复后不重复尝试同一个假设。

相同候选的训练/验证执行可以跨搜索作业复用：搜索预算、反思提示词或选择算法变化，不单独使执行成绩失效。索引位于评测目录的 `candidate-cache`，只记录摘要与报告相对路径；命中后仍由现有报告恢复流程校验策略版本、精确题目集合、重复次数、数据、执行/评分配置及产物。完整成绩直接保留，已执行但裁判失败或未决的题只重评；取消批次中的未执行题继续补跑。部分检查点不等于完成，不能直接用于通过判定；完整报告不会被较差检查点覆盖。缺少必需 token 等无法通过重评修复的执行不进入这条复用路径，显式 `unknown_token_policy=worst_case` 仍遵守原有保守成本语义。当前目标分数和发布门槛重新计算，不沿用旧的“通过”结论。缺失、损坏或身份不符按未命中处理；最终 holdout 不使用此共享缓存。运行时检索、控制语义或评测条件变化时隔离缓存，避免旧成绩混入新版实验。

报告容量与模型输入容量相互独立。评测配置 `max_report_bytes` 默认仍为 32 MiB，可显式配置至 1 GiB 的统一文件硬上限；这不是预分配内存，也不扩大单题轨迹、裁判请求或 HTTP 上限。GEPA 可另设 `holdout_max_report_bytes`（不设置或为 0 则继承评测配置），只覆盖最终留出批次，包括候选与缓存 L0 合并后的报告；不会改变搜索小批与选择验证的配置身份。容量超限仍报错，不能裁掉题目或轨迹后标记完成。保存过程分阶段释放 JSON、Protobuf、JSONL 临时副本，清单最后发布；原有文件格式、哈希校验、完整证据和顺序保持不变。大报告仍需要与轨迹规模匹配的内存和磁盘，并非无界存储。

反馈写回只改变记忆库修订、快照 ID 或策略 ID，但种子的行为版本不变时，新作业沿用同一用户、同一等级最近一次可校验的冻结种子。状态中的 `seed_source_job` 标明来源；本轮反证仍从当前权威记忆库读取，不被旧快照替换。复用前重新校验种子全文与行为版本，缺失、损坏或不匹配则使用本次合法种子。关闭 `cache_evaluations` 时不沿用旧种子。该机制保留原始执行来源标识，不改写历史报告，也不跳过执行环境、题目或评分配置的缓存有效性检查。

命令参数显式引用的宿主文件内容也参与候选执行指纹；同一路径的入口脚本变更会使候选缓存失效。本包 CLI 自身不按二进制内容区分，避免仅重编译搜索代码就使执行成绩失效；实际运行语义由版本指纹区分。shell 命令内部路径、动态模块与传递依赖不自动扫描，部署方仍须在这些依赖变化时更新 `agent.revision`。独立 L0 缓存契约保持不变，修改宿主业务代码后同样需要正确更新 revision。

普通反思和 COMBEE 分组/汇总共用一次有界纠正：组件越权、来源无效、未开放的重规划能力，以及结构/字段错误可在剩余调用预算内纠正一次。组件纠正沿用一条相关训练反馈；来源和格式纠正只使用原草稿、批准来源与父组件，不重新执行 Agent。增量索引始终对应同一父策略。COMBEE 中途失败保存实际子草稿，不重跑已完成分组；修复再次失败、预算不足或敏感内容校验失败仍拒绝。通过纠正不代表有效进化，候选继续接受授权校验、差分预检、真实评测和发布门禁；复述父策略仍按重复节点处理。

动作组件纠正优先保留有真实 allow guard、尚未执行且已有落定轮数的训练行，不增加反馈条数。重复添加同 scope/actor 的循环规则也进入一次格式纠正：只有能唯一定位父规则且草稿具有行为差异时使用 set，歧义或等价草稿返回无改动；不自动合并规则，不放宽唯一性检查。

反思输入保留经验的 scope 与当前 condition；正文已改写时提供 original_content。经验组件兼容正文字符串，也支持 `{content, trigger_pattern, observed_operations}` 对象。可基于误注入证据收窄或澄清触发条件，不能换成无关工具或取消任务要求。`observed_operations` 要求同分支近期有真实已执行的动作，不能由文本提及代替；前置规划经验可以不设置。

模型调用反馈中的 `experience_query` 只保留 scope、经验 ID、观察到的操作和应用状态，不重复请求历史。`application_status=applied` 表示注入已核验，不能仅凭查询 ID 宣称生效。条件和正文一起通过真实候选评测；不因工具返回成功就允许省略用户明确要求的文件或图片验证。controls 不再重复携带同一份来源记忆。

### 让控制能力获得真实机会

机会来自训练执行，不来自留出集，也不扩展动作授权。每次父策略训练后，程序记录具备实际干预条件的训练题 ID。后续对应组件的批次保留一个已知机会，其余仍按原批次顺序覆盖训练任务；运行时重新检查条件，不把历史命中当作新节点已命中。

反思输入只提供获选组件，并优先保留与该组件相关的执行片段。草稿编译后，`control_preflight` 用新策略重放这些已采集查询，检查它能否改变父策略的实际决定。默认轮换模式下，没有差异触发的新规则记为 `untriggerable_controls`，不再为它执行一整批 Agent。此阶段不调用模型、不执行业务工具，结果仅代表存在触发机会。

模型改错组件时，最多修正一次：保留获选组件、来源、限制和一条原训练反馈，优先选择包含该组件可执行证据的记录；编排记录保留实际 `schedule_plans`。不重传越界草稿或整批轨迹，不加入验证／留出内容，仍受同一输入大小和模型调用预算约束。仅修正来源 ID 时不发送执行反馈。

空草稿或编译后没有实际组件变化，保留父版本并记录 `duplicate` / `skip_reason=no_behavior_change`，不启动候选试次。判重比较经过 Protobuf 解析的授权组件，空数组、空字符串、false 的省略与显式表示不会制造一个新候选；已导出策略的公开版本 ID 保持兼容。主动移除已有生成规则或禁用经验仍是实际变更。
编排机会按 action_id 实例计数，同名技能多实例也有候选机会，但顺序改变必须另有收益证据。独立并行任务允许返回空草稿，不能为满足等级统计而人为串行。

随后仍要启动真实候选 Agent。L1 必须在实际模型请求中找到改写正文；L2 编排必须有满足依赖顺序的真实执行记录，参数护栏须确认被拒绝动作未执行；L3 重规划必须确认上下文进入下一次模型请求，停止必须有宿主停止回执。真实应用记录和性能收益分开保存，命中本身不等于有效提升。

`replan_on_failure` 是可选的 L3 原语，旧策略默认关闭。组件在 action 结束时识别显式 `status=failed`，或已执行结果顶层的 `status=failed/error/rejected`、`success=false`、非零数值 `exit_code`。字符串结果最多解析 64 KiB，不解释自然语言、不递归猜测嵌套业务语义，也不改变工作流成功状态。失败仅计入该 action 关联的 loop；有在途动作时保留观察，下一次完成的控制步骤消费本次所见计数，之后到达的失败仍保留。只有基础规则允许 replan 且预算尚余才重新规划，耗尽恢复预算不会仅因失败而停止任务。

### 同口径选择与独立验收

搜索先评测种子，再在同一验证集运行一次 L0 基线。节点记录 `optimization`：质量和配置中的时延、token 约束为可行性条件，无效 loop 目标记录剩余差距；前沿仍保留局部有优势的分支以供融合。最终候选优先按可行性、距目标的差距、逐题非退化比例选择，再比较原 fitness。验证数据不进入反思输入；训练反馈负责修改，验证指标负责选择，留出集只评测冻结后的最终候选。

单次对照仍受模型与网络波动影响。版本的应用回执用于证明行为发生改变；确认收益时还应在固定版本、相同任务与预算下做重复配对评测，并保留逐题差异。不能把没有实际应用证据的分数上升归功于策略。

## 评分目标与预算

真实成功/失败由既有规则、模型评分及安全检查决定。逐题 fitness 为：

```text
fitness = task_pass
          - invalid_loop_weight × invalid_loops / (invalid_loop_scale + invalid_loops)
          - token_weight × tokens / (token_scale + tokens)
          - latency_weight × duration_ms / (latency_scale_ms + duration_ms)
```

默认权重为无效 loop `0.2`、token `0.05`、时延 `0`，三个成本权重之和必须小于 `0.5`。
重复试验先在每道题内取平均。严格改善或不退化筛选要求同一任务集合、相同计量口径的原始无效 loop 均值不得上升，再比较任务通过率与 fitness；Pareto 中间筛选允许保留局部优势，见下文。完整验证后的 winner 按前述 optimization 比较可行性和距部署目标的差距，不只依赖有界 fitness。不能用答对率提高或有界成本饱和来掩盖更多无效循环。例如 [0,10] 的均值为 5，不能因归一化后较好而替代 [1,1] 的均值 1。模型调用数等其他指标继续保留在逐次报告中。
此检查针对搜索时的训练/验证样本，不保证未见任务上的收益。冻结版本仍必须在 holdout 与基线独立比较；原来的通过率、loop 降幅等发布门槛保持不变，失败时不发布、不读取 holdout 轨迹继续反思。

轮换到 L1 时，如果原定经验没有在同批父轨迹中实际应用，会先从该批已有应用回执的经验中，
选择历史探索次数较少的一条；没有可用经验才转向有执行证据的 L2/L3。已停用经验仍保留恢复探索机会。
这一选择只复用现有训练证据，不额外调用模型，也不读取验证或留出轨迹。

`patience` 统计有结论但前沿未改善的批次；仅含评测异常、不确定结果或预算跳过的批次，
既不增加也不清零已有停滞计数。重复候选和真实策略失败仍计数，总轮数、模型调用、题数和超时上限始终有效。

`acceptance=pareto` 只放宽中间反思与重组的筛选：任务集合与计量口径必须相同，至少一题质量改善，
或某题质量不降且 fitness/循环/token/时延效率之一改善，才算局部优势；未知指标不算优势。
同题失败换来的低耗时不计为该题效率收益。候选仍需完整验证，按配置的前沿规则取得后续选父资格，
并不自动发布。整体 winner 的选优与最终发布门槛不随中间筛选放宽。

若最终要求“成功率不降、无效 loop 至少下降 15%、平均 Agent 耗时不增加”，在 agent-evaluation 的 gate 中
同时设置 `max_pass_rate_drop:0`、`min_invalid_loop_reduction:0.15`、`max_latency_ratio:1`；
搜索 objective 同时给 latency_weight 非零权重。减少循环次数并不必然减少墙钟时间，长请求、重试、
更多输入 token 和并发关键路径都可能抵消收益。trial.duration_ms 是实际宿主执行耗时，不包含之后的模型判分。

L3 搜索需要种子本身为 L3、开启 control_learning，并有可收紧的基础 loop_rules；
检查 tree.available_components 是否包含 loop_rules。最终核验还应检查生成规则的 source_experience、
匹配条件及真实执行中的 loop.decision/应用回执；只有等级标签或经验正文变化，不能证明循环控制产生了实际效果。
`invalid_loops` 默认是规则观察到的 `invalid_loop_lower_bound`，并不等于全部业务浪费。
在任务评测配置中启用 `judge.loop_review_prompt` 后，改用同一次评分请求给出的逐轮模型估计；
每条结论绑定真实轮次和事件。详见[无效 loop 评测](19-datasets-and-benchmarks.md#评测无效-loop)。
规则下界仍独立保存，模型评审缺失或不完整时不回退为零。发布门禁读取相同口径，并拒绝将基线 0 到候选 0 当作正比例下降。
默认要求启用非零权重的指标可观测；token 应在每次模型结束打点提供 usage，不能只提供一个未经调用记录支撑的汇总数字。
模型超时后可能确实没有 usage。此时可在 gepa.json 显式设置 `unknown_token_policy="worst_case"`：
仅将未知 token 的归一化成本按其上界 1 参与排序，仍扣除完整 token_weight，不改写 Trial 的未知用量。
每道题的 `unknown_token_trials` 记录这种情况的次数；存在时，fitness 和 token_efficiency 是保守下界，不是精确成本收益。
该选项不接受缺失/不确定的业务评分或循环证据，也不放宽发布门禁；配置 max_token_ratio 时仍要求完整成本观测。
缺省 `unknown_token_policy="reject"` 保持原严格行为。策略参与评测上下文指纹，缓存不跨这两种口径复用。

## 可选的分组聚合反思 ComBEE

参考 [GEPA ComBEE](https://gepa-ai.github.io/gepa/guides/combee/)，当训练反馈较多时，先分组提出局部改进，再汇总成一个组件。默认 `reflection_strategy=single`，仍只进行普通单次反思。

启用方式：在 gepa.json 设置 `"reflection_strategy":"combee"`。可选 `duplication_factor` 默认为 2，范围 1–4；`aggregation_prompt_file` 默认读取反思提示词同目录下的 gepa-aggregate.txt，配置相对路径时相对于 gepa.json。两个提示词都属于外部配置，不需编译。

对经过长度限制后实际进入反思包的 n 条反馈：

1. n 少于 4 时使用普通反思。
2. 对每个获选组件，将反馈复制 p 次、按 seed 洗牌，分成 k=floor(sqrt(n)) 组。
3. 每组调用一次反思模型，产生该组件建议；每份建议立即做隐私、授权、范围及长度检查。
4. 将 k 份有效建议、原因和父组件交给汇总模型，产出该组件的完整改写；汇总不接收验证／留出题目。
5. 合成一个候选，继续执行同一套小批次、验证和最终准入。

例如一个组件、4 条反馈、p=2，会产生 2 次分组请求和 1 次汇总请求，总计 3 次模型调用；两个组件则为 6 次。开始前检查整次候选所需的请求数，预算不足就不启动半套分组反思。分组、汇总与失败请求全部占用 max_model_calls，不另开隐藏预算。

复制与打乱可能使某组比原包更大；此时保留输入、标准、输出、检查和指标，标记 evidence_truncated，必要时减少组内记录并标记 feedback_truncated。仍超限则结束该提案，不超出 max_input_bytes。汇总建议同样受输入上限约束。中间结果按节点、组件、阶段分别落盘，恢复时可检查已完成阶段；外部请求结果未知的中断提案记为 interrupted，不猜测其结果或退还已占预算。

| `nodes[].reflection_stages`                             | ComBEE 已完成的 map/reduce 阶段、组件、文件前缀与反馈数量；普通反思没有此字段                                                  |
| `nodes[].duplicate_of`                                  | 相同行为版本首次出现的节点；重复节点不另行评测                                                                                 |
| `frontier / frontier_mapping / winner / active`         | 当前前沿并集 / 每个任务或目标对应的最优候选 / 验证阶段选中节点 / 尚在处理节点                                                  |
| `batch / reflection_batches / training_batches`         | 尚未结束的提案批次及冻结计划 / 已创建批次数 / 已采样的训练批次数；batch 结束后为 null                                          |
| `merge_attempts / merge_due`                            | 已尝试双亲、祖先和对应节点 / 是否有待尝试的重组机会                                                                            |
| `rounds / model_calls / trials_used`                    | 已占用的预算；中断请求不能假定没有费用                                                                                         |
| `evaluations`                                           | 按行为版本、任务子集、配置形成的缓存索引，含报告路径、哈希和 attempt；拼接报告有 source_reports，trials_reserved=0，仅补跑缺题 |
| `holdout_started / selected_version`                    | 是否已冻结最终比较对象 / 选中的完整行为版本                                                                                    |
| `status / stop_reason / started_ms / finished_ms`       | 整棵树的状态、停止原因和毫秒时间戳                                                                                             |

`versions/*.json` 包含完整 RuntimePolicy，可重算 policy_id 和 agent_version_id。记录文件通过临时文件、fsync 和原子替换发布；目录/文件限制为当前用户可访问，拒绝符号链接路径。

常见分支终态包括 accepted、rejected_minibatch、rejected_merge、duplicate、skipped_merge、skipped_perfect、not_selected、unobserved_controls、unobserved_changes、inconclusive、error、interrupted。它们分别保留有效成绩、筛选拒绝、跳过原因、证据缺口或固定错误码；被批次排名淘汰的 not_selected 不运行完整验证。unobserved_controls 表示缺少当前规则的真实应用证据；unobserved_changes 表示训练与验证均未观察到相对父节点的实际决策变化。二者均不表示策略在所有任务上永远无效；查询次数和规则解释不算应用回执。
重组节点的 screening 记录双方与子版本在相同验证子集上的成绩；不是一次训练反思。

## 查看、取消与恢复

### 搜索证据与本轮执行证据

候选节点的 `control_coverage` 可以保留同内容规则在训练和父节点中的使用证据；`validation_control_coverage` 单独保存本次验证的实际查询、触发和应用次数。发布结果的 `gate.control_coverage` 仅来自当前最终评测，合并历史后的数据另放在 `gate.historical_control_coverage`。默认展示这些信息，不以全能力覆盖阻挡效果达标的策略；显式开启严格能力验收时使用本次最终评测回执，历史上某次应用不能代替当前应用。

`screening.applied_changes` 按任务和边界记录候选相对父策略的实际决策差异。程序在同一份已采集查询上本地回放父策略，再核对候选的执行回执；不额外调用模型或重新执行 Agent。停止注入、移除限制等改动，也必须能关联到真正执行的模型/动作或已提交的控制边界。仅修改解释文字不算控制条件变化。

Pareto 筛选中的局部收益，只从存在上述差异的任务计算；没采用改动的题，其随机时延改善不能成为局部优势。原始逐题得分、耗时和循环数仍完整保留。重组候选分别对两个父节点记录 `screening.parent_applied_changes`；完整验证在 `validation_applied_changes` 中按父节点 ID 记录。训练与验证都没有观察到任何决策改动的候选记为 `unobserved_changes`，不作为已验证的新版本。

控制草稿只改变 `reason`、未改变可执行条件时记为 `duplicate`，`skip_reason=no_control_predicate_change`，不重复运行 Agent。L1 的经验正文和适用条件仍参与去重，不会因为措辞不同而丢弃真正的经验改写。

纯删除生成控制规则也先检查训练中的实际作用：用候选策略回放父训练轨迹，比较模型上下文、动作准入、调度依赖和循环决定，并核对实际执行回执。若没有行为差异，`control_preflight.pure_removal_no_effect=true`，不再运行该子策略。移除了真实生效的约束时继续正常评测；同时改写 L1 内容、条件或启用集合的候选不按纯删除处理。预检不证明质量改善，正式评分与发布门槛保持不变。

反思请求仅展示本轮获选组件对应的原语与基础规则；纯 L1 请求不携带无关控制配置。控制反思仍保留合法经验来源和限制，COMBEE 的每个子请求采用相同裁剪。裁剪只改变展示视图，不扩大候选授权，也不修改训练反馈或评分。

已开放且本轮获选的 operation_budget 可以附带 `observed_bindings`：最多 4 个真实重复派发 guard 的 operation、target_scope、prior_operation_rounds 和 evidence_ref。引用指向当前请求的反馈，不沿用其他分组或上次纠正的索引；同身份保留某次真实最大观察，不累计不同 Run。辅助绑定只用既有输入预算的剩余空间，不能挤掉反馈。包装委派与实际子操作分别计数，不能把子技能的计数移给包装调用；提示绑定本身不新增权限或自动选择组件。

### 从失败证据生成可执行修正

循环评测与控制计数分开处理。完整的模型轮次评审按 `run_id / execution_id / loop_id / iteration` 绑定为 `iteration_assessment`，保留 keep/waste 与简短理由；数字和字符串形式的 iteration 使用相同 Protobuf 规范身份。缺失、不完整或不匹配的评审不被补成确定结论。

`loop_control.reviewed_waste_after=N` 只表示该次训练执行中 N 轮之后的已执行尾部均被评为浪费。它在裁剪反馈之前计算；后面还有必要工作的中间浪费不能变成可截断尾部。候选上限仍不低于 `min_iterations`，并且必须存在超过该合法上限的实际轮次；N=0 的全空转分支同样可以探索，但不能跳过最低轮数。该字段不证明 actor 级规则对其他任务也安全，仍须通过真实任务评测。原结构重复计数与有界恢复能力不依赖模型评审。

同一 scope/actor 的必要步骤形成 `required_iteration_floor`：先汇总本批完整训练评审，再裁剪反馈，避免只看到重复执行的浪费而截断第一次执行。缺少某轮 loop 打点时，同一 run/execution/loop 的必要 action 仍计入下界。支持安全收尾的规则仅豁免原始轨迹确认的最后纯答复，不豁免工具工作。新增或收紧轮数上限还会回放完整训练轨迹，命中后若截断已知必要步骤，预检记录 `known_keep_truncation` 并拒绝该候选；不追溯改变继承规则。

保守模式（`aggressive_controls=false`）也能探索带收尾约束的轮数上限：必须有明确 `actor_id`、已验证的浪费后缀、`require_finalization=true`，且观测到宿主支持 `can_finalize`。反馈摘录、机会路由和可编辑绑定采用同一条件；必要工作下界、完整轨迹预检、实际生效和质量评测仍保留。无收尾能力或仍有待完成动作时，运行时继续原流程；没有上述约束的全局轮数截停仍需显式启用激进模式。该机制不把所有参数不同的查询都判成无进展，也不在主 Agent 热路径新增模型调用。

可编辑绑定携带程序计算的 `budget={field,min,max}`，同时用于草稿校验；无解区间不发送给模型。绑定错误在 `reflection_calls[].control_binding_error` 保存固定原因码、更新下标和可选可信预算，并进入已有的一次纠正，不保存模型的任意字段或错误绑定原文。已停用经验保留自己的轮转恢复机会；恢复后仍需真实评测，不因原先没有应用回执而永久让位。

`round_robin` 保留当前确有执行机会的控制组件；没有机会时，可再次选择已有训练证据的其他控制组件，按实际组件选择次数安排，不限制为“只探索一次”。实际用过的 L1 经验继续参与轮换，`all` 不改组件集合。辅助候选探测超出输入预算时跳过该候选，其他异常正常报错；不会扩大输入预算或远程调用次数。

- 对数据集明确标注的成功依赖，若真实训练批次同时包含前后操作、任务短语也命中，程序会把错误的 `require_success=false` 校正为 `true`，记录 `schedule_contract_repair`。这只用训练证据，不读取验证或留出任务来改写规则，不新增模型调用。
- 当基础 L3 已在最小无进展阈值处 replan，继续降低阈值无法产生不同决策。开放的 `bounded_recovery_budget` 允许降低 `max_replans`；0 表示达到原无进展条件后停止本分支。首次失败、独立分支和在途动作不因这条改动被直接终止。
- 不支持的 `replan_on_failure` 草稿最多进入一次有界能力修复；修复输入只包含可用能力及紧凑训练反馈，不无限重试。
- 对同目标跨执行实例的重复失败，使用 `repeat_failed_target`，详见[运行时控制](16-runtime-controls.md)。反思输入中的 `failure_key_candidates` 是观测到的重复参数，不是自动认定的业务身份；编译、差分预检和真实评测继续验收生成规则。

主动取消的外层作业和搜索树都使用 `cancelled` 状态；即使取消发生在评分完成与发布之间，也不会继续发布。可显式 retry；旧实验上下文与新执行语义不混用。

HTTP 与原生管理入口使用同样的 operation。原生 Python 示例：

```python
status = evo.manage("agent_evaluation.status")
tree = evo.manage("agent_evaluation.tree", {"job_id": job_id})
evo.manage("agent_evaluation.cancel", {"job_id": job_id})
evo.manage("agent_evaluation.retry", {"job_id": job_id})
```

管理请求携带当前用户身份，只能访问自己的任务与树。HTTP 使用既有 `/v1/invoke`，例如：

```json
{"operation":"agent_evaluation.tree","request_id":"inspect-tree-1","job_id":"从 status 获得的 64 位任务 ID"}
```

进程异常退出后，同上下文中运行中的 GEPA 任务自动重新排队。完整评测缓存通过报告哈希校验后复用；已生成策略从文件恢复。中断于反思调用时无法确认模型是否完成，节点记为 `interrupted`，消耗的预算保留，继续后续轮次。
同一组评测已有有效检查点时，恢复会核验配置、报告清单和产物哈希。已完成 Agent 执行但模型评分失败或不确定的试次只补评分，保留原试次 ID、轨迹、调用指标和执行时延；没有可复用执行证据的试次才重新执行。未完成报告仍不会作为已通过成绩使用。`cache_evaluations=false` 保留训练和验证的重新执行语义，最终留出评测的恢复仍复用有效检查点；重新执行继续占用原有保守预算，仅补裁判不重复扣减 Agent 执行次数。
暂态裁判错误或模型评分不确定最多自动恢复一次，其他已确定题目保持原成绩；持续不确定仍阻止进入可比较成绩，不反复请求直到通过。仅模型复评产生的报告也可用相同配置的 `--resume-report` 继续未决评分：完整配置和来源指纹链必须匹配，已确定成绩复用，缺少可复用执行就拒绝，绝不转而启动 Agent。长回复使用同预算的头尾预览，省略中段仍可通过原路径申请补查；完整原始证据不被修改。
单次评分内部，裁判未主动补查且当前目标仍未知时，会限量提供同轮被截短的答案或工具结果原文；与主动补查共享次数、模型调用和总输入预算，单次最多四个字段。工具结果按 event_id 对齐原始事件，不以压缩视图下标定位，不自动读取模型请求、输入或其他轮次。同一字段只补一次，已补字段不占下一次名额；预算不足保留未知，补后仍可能失败或未知，不以重复投票生成通过结果。

目标模式可配置 `judge.consistency_prompt: "prompts/task-consistency.txt"`，在主裁判协议校验后核对判分理由与结论。业务离线 GEPA 准备入口自动启用。短核验只读取各轮请求、验收标准及主裁判的目标结论/理由，不重复发送工具轨迹、模型上下文或产物。它检查明确缺项被豁免、额外增加要求、条件分支矛盾及理由与结论相反；执行事实仍由主裁判依据原轨迹核验。核验器只返回目标 ID 与固定问题类型，不直接赋分；发现矛盾时原裁判使用同一证据重新核对，次数受 `max_repair_attempts` 限制。持续矛盾、核验不可用或预算耗尽都产生评测错误，不能成为策略通过或反证。

理由冲突或核验器 JSON 格式错误耗尽批内修复后，也可使用上述同批唯一的一次自动补评机会；只重评未决题的原始执行，已确定评分不重做。它与其他暂态评分错误共享恢复额度，不为每一种错误另开次数；再次失败仍保持未决。

短核验共用已有模型、凭据、超时、取消和 `max_model_calls` 预算，计入报告的模型调用数与评分尝试数；HTTP 429 保持原有限流暂停语义。未决目标不额外核验。核验提示词正文参与裁判身份，因此启用或替换后必须重新验收旧轨迹，不能复用旧评分。通过核验的批次在 `evidence.judge_batches[].consistency_review` 中记录 `status=complete` 和 `reviewed_goals`；失败诊断只保存受约束的目标 ID/问题类型，不保存任意响应正文。未配置该字段的既有接入方式保持原有行为。
搜索为最终留出保留时间：有显式 `holdout_reserve_ms` 时沿用配置；否则按实际并发执行波数估算，再保留 1.5 倍安全系数和至少总预算的 20%。一波最多为评测器配置的 `parallelism` 个新增 Agent 执行，末尾不足一批仍算一波。小批补跑不按串行每题时间外推，满并发观测不重复折算并行收益；纯缓存和纯补评分不更新 Agent 吞吐估计。读写与评分开销仍计入观测墙钟，实际已消耗时间与执行预算不受估计器调整影响。

评分或反思 API 返回 HTTP 429 时，GEPA 作业以 `gepa_model_rate_limited` 停止，保留当前代、已生成候选和评测检查点，不继续尝试后续代或进入留出评测。限流解除后使用 `agent_evaluation.retry` 接续；已消耗预算不退还。业务失败仍参与原有候选筛选，不触发此暂停。

普通反思草稿误填未批准的控制来源时，记录 `control_source_not_approved`。模型预算尚有余量且 `control_learning.max_attempts >= 2` 时，只额外修正一次：输入原草稿、合法来源和控制约束，不重复发送训练轨迹，也不重新执行 Agent。组件不替模型选择来源，修正结果仍须通过原有授权和隐私校验；持续错误或预算不足就结束该节点。基础规则的 `rule_id` 不是经验 `memory_id`，不同执行实例的无效 loop 数也不等于单实例 `max_no_progress` 计数。
普通反思改动了轮转未选中的组件时，记录 `gepa_component_not_authorized`，并在同一次数与预算约束下进行一次紧凑修正。修正输入只保留原草稿、获选组件当前值、合法来源和控制约束；训练轨迹不重复发送。程序不会自动采纳越界内容，第二次结果仍须通过原有组件授权、来源、隐私和行为兼容检查。
训练或验证批次只有单个 runner 超时时，检查点最多补跑该未完成试次一次；同批已经完成且具备评分和目标指标的试次直接复用。再次超时仍保留 `inconclusive`，不会删除慢任务、用较小样本冒充原批次或伪造成绩。
主动取消不会自动重启；可显式 retry。retry 不重置预算、截止时间或留出集候选。更换数据/模型/宿主 revision/配置后是新实验上下文，不复用旧成绩。
统一活动边界的检索状态默认值升级也会改变评测上下文：旧报告保留供审计，但不会直接续用旧搜索或旧发布准入结果。
相同新上下文内的恢复、完整成绩缓存和逐题补测仍正常复用，不在每个 run 重置版本。

只修正裁判而未改变 Agent、数据集或策略时，可先用 `dataset run --regrade-report` 重评原轨迹，再通过 GEPA 配置的 `seed_report_file`（种子）或 `baseline_report_file`（L0）引用完整的选择验证报告，避免重跑 Agent。两个入口共用版本、题集、裁判指纹及完成状态校验；不接受旧口径评分、缺题、其他策略或训练/留出报告。报告正文摘要也参与搜索身份，替换文件后不能继续使用旧搜索检查点。种子节点的 `validation_source.status=imported` 和 `report_sha256` 记录复用来源，控制命中证据仍从报告的真实轨迹计算；导入不改变评分或发布门槛。业务离线入口可用 `--prepare --seed-report 路径 --baseline-report 路径` 同时引用二者；两个报告参数均仅用于新实验准备，运行/重试阶段不可替换冻结成绩。

恢复会校验父引用只能指向较早的有效节点、双亲无祖先/后代关系、共同祖先、深度、批次任务和预算。旧单父记录可规范化为 parents，但本次算法指纹升级会为新提交建立新上下文，不把旧算法运行中的试验直接混入新的搜索。已有发布包和离线加载接口保持兼容。
隔离试验只继承显式绑定的标准输入输出，不继承组件服务锁；父服务中断后，已完成缓存仍可恢复，未完成试验重跑时重新占预算。

同一 seed、上下文与有效反证摘要完成后，不会因为发布改变 parent 或消费反馈而自我触发下一棵树。后续新记忆形成新的 seed，或下次显式离线调用读到新增的匹配反证，才进入新搜索；相同输入再次调用仍去重。不同搜索不共享搜索树；其中完全相同的候选、题集和执行上下文可按上述完整报告校验复用训练/验证执行。目录保留历史树供审计，容量清理由部署的保留策略管理。

## GEPA 反馈回到唯一记忆库

闭环为：训练日志形成记忆 → 编译并冻结种子 → GEPA 真实父子配对 → 管理层提交反馈 → 更新同库修订/状态 → 下次编译新种子 → 验证和留出验收 → 发布不可变策略包。

| 组件 | 责任 |
| --- | --- |
| 搜索 | 记录父子策略、应用回执及同题效果，不直接编辑记忆文件 |
| 归因 | 过滤错误/未生效试次，区分原文独立效果、条件化修订和组合效果 |
| 记忆管理 | 核对用户和来源版本、按任务去重、原子提交，维护原经验状态与公共可信度 |
| 种子编译 | 采用已支持且背景匹配的增量；来源失效或能力不兼容时保留原可运行种子 |
| 发布 | 沿用质量、收益、覆盖与 holdout 门槛，记忆 supported 不替代发布验收 |

### 数据范围与组合归因

仅搜索 `train` 划分的有效父子结果回流。要求任务 ID、任务版本及 repetition 一致，两侧完成有效评分，并观察到行为变化。业务质量/通过率/无效循环退步优先记为负向；错误、超时和不可判定不变成业务反证。

`train` 在此表示 GEPA 搜索视图的内部角色。业务示例中对应原 val 的 150 道搜索题；原业务 train 400 道负责第一阶段记忆积累，另 50 道选择验证和 200 道 holdout 不反馈入库，也不把原业务 train 复制到第二阶段。

A+B → A+B′ 有收益时，记录“在这个版本的 A 下把 B 改成 B′”，而不是“A、B 都应升级”。A+B → A′+B′ 保留整组修改，编译时整体校验背景和来源；分别测试的两个改动不能随意拼接。原文 A 独立启停的配对才可升级/降级 A；A 的改写版本失败不能归罪于原 A。

多亲融合节点如果只有选择验证证据，不将该验证成绩转为经验支持票；发布版本仍保留完整父子关系与验收报告。修订、原经验和公共可信度的具体字段见[私有记忆](13-private-memory.md)及[公共记忆](14-shared-memory.md)。

### 持久化与恢复

`EvolutionMemoryStore.gepa_feedback` 与原 entries 同存在一个 PB/JSON 中。`search/tree.json` 是搜索审计，`search/memory-feedback.json` 是带指纹的投递包，不是另一个记忆库。作业 `memory_feedback.status` 从 pending 变为 committed，结果记录原库修订和反馈记录数。

消费顺序为“提交私库 → 同步原公共台账/视图 → 确认已消费”。崩溃、锁占用或视图写入失败保留恢复点；同题重放不加票，旧版本证据不覆盖新经验。训练后的正常整理仍可读取新增字段，不因结构化反馈的序列化顺序产生虚假并发冲突。

作业中途取消、异常或因搜索改版无法继续时，后台可恢复 tree 中已经形成的完整训练配对。恢复核验原作业上下文、冻结种子版本和用户，复用来源与 train 隔离检查；在运行节点和留出复测不在此范围。每个停止的 attempt 只扫描一次，重复交付不重复计票。作业继续保持取消／错误状态，反馈入库不等于策略发布；损坏检查点记录固定恢复错误，不把一份旧结果的问题扩散到其他作业。

待投递包也执行文件摘要、非空协议结构、冻结种子和 train 来源验证；一份损坏记录标为 rejected，不阻塞其他作业，不算入库成功。执行或评分上下文已变化的历史投递标为 obsolete，仅保留审计。裁判一致性核验提示词的正文同时绑定作业、基线和候选缓存身份，热替换后不会沿用旧评分口径。

新一次显式启动可以先消费同口径历史反馈，再编译本次起点；消费旧反馈不会吞掉本次启动。已有作业正常完成的写回不自动引发无限续轮。

反馈不修改已冻结父策略或已发布包，也不立即触发下一轮搜索；下一批学习或下次显式离线搜索使用更新的同一个库，避免“反馈入库—搜索—再入库”的无输入循环。配置、任务和评分上下文变化时继续执行原缓存有效性检查。

失败反馈也参与下一轮反思：管理层只选取当前用户、来源修订、完整组合背景和执行评分上下文匹配的 regressed/conflicting 训练记录。作业冻结最多 4 条、总计不超过 16 KiB 的摘要；更新审计时间或重复报告引用不产生新输入身份。这是作业输入，不是记忆库副本，原始条目仍只保存在权威库。

每次反思再按获选组件与当前父策略复核这些摘要，把已尝试改动、归因类型、正负任务数放入 prior_search_rejections。同一搜索内刚获得的反证也走这条路径。先为匹配的反证预留有界空间，再装填当前训练证据，避免长轨迹填满输入后遗忘刚失败的提案：历史最多 4 条，条目合计不超过 8 KiB 和 max_input_bytes 的八分之一，基础字段与历史合计不超过总预算的一半。首条当前证据仍放不下时退还历史空间，按原有规则重新装填，不增加总输入上限。无匹配历史时请求保持原样。旧判决不会无条件约束不同背景的新策略，也不会据此否定组合中的每条原经验。

后台把“评测结果完成”和“记忆内容变化”分别记录：前者刷新结果与投递回执，后者才允许自动提交新的种子。另一用户或另一等级完成评测，不会把本用户刚提交的反证变成一场额外搜索。离线重新调用会重新读取原库；新反证可开启下一场有明确预算的搜索，但既有基线和候选执行缓存仍按原身份复用。

## 离线加载预先进化版本

将通过验收且实际发布的 `published-version.json` 作为可信部署文件。它包含完整策略、来源经验快照、触发条件、检索参数、经验模板和控制规则；导入不需要原来的 memory 数据库、训练配置、提示词文件或实验目录。

固定候选评测通过并发布后，自动写入 `agent-evaluation/<job_id>/published-version.json`；GEPA 作业继续使用
`agent-evaluation/<job_id>/search/published-version.json`。未通过验收或未获得发布资格的候选不导出。
重启时，已登记发布但缺少文件的版本会按原验收记录校验并补导出，不重新执行 Agent 或调用评测模型；
这不会把旧评测上下文的通过记录当作新上下文的准入。已有且一致的文件不会重复写入，
文件内容与发布记录不一致时明确报错。

在组件服务配置中删除 `policy_evaluation_file`，加入：

```json
"policy_version_file": "versions/published-version.json"
```

保留当前应用正常运行所需的身份、认证和打点配置；其中的 application/user 需要获得该版本授权，scope 和运行能力需要覆盖策略要求。宿主的模型密钥、工具实现仍由宿主管理，不包含在策略包中。离线模式不读取 `runtime_config`、`experience_template_file` 或历史经验库，也不根据当前记忆重新编译策略。

策略行为使用包内冻结值，不要求当前部署的检索默认值、模板或请求字段绑定与训练时一致。当前部署显式规定的上下文上限、基础动作规则和循环上限仍作为限制检查；导入不会放松这些限制。组件验证版本哈希和验收标记，新 run 绑定当前 conversation/run 身份，`agent_version_id` 仍指向同一冻结行为版本。HTTP 与原生打点使用相同校验。

该模式自动关闭轨迹学习、共享管理和后台策略评测，保留正常轨迹采集；没有反思模型请求，也不会把业务 run 标成 evaluation trial。不同用户不会获得这个私有版本；用户或等级不匹配时返回 L0 和 `offline_policy_incompatible`。缺少打点能力、作用域或违反当前限制时返回明确错误，原生客户端保持既有 fail-open 降级行为；不能把降级执行计为该策略的有效评测。
这里的离线指进化组件固定版本运行；主 Agent 的模型/工具是否联网由宿主决定。文件是受信部署输入，SHA-256 用于完整性核验，不是签名服务；部署方负责保存、分发和撤销文件。

离线版本冻结了当时的私有/公共经验关系；它不持续接收在线记忆撤回。需要撤销时停用或替换版本文件并重启组件。在线部署继续使用当前记忆状态核验。

验证导出后独立生效时，使用新的任务集和空状态目录。L0 不加载策略，L1–L3 对照组只在评测 `variants` 中增加 `policy_version_file`，其余模型、工具、预算和评分配置保持一致。评测会走实际离线加载校验，而不是直接绕过校验替换内存中的策略。配置示例见第 19 章。

## 与上游 GEPA 的逐项对照

对照的是 [GEPA 核心接口](https://gepa-ai.github.io/gepa/api/core/optimize/)、[合并提案实现](https://github.com/gepa-ai/gepa/blob/main/src/gepa/proposer/merge.py)、[提案筛选策略](https://github.com/gepa-ai/gepa/blob/main/src/gepa/strategies/proposal_selection.py) 与 [ComBEE](https://gepa-ai.github.io/gepa/guides/combee/)。Hermes 将技能交给 DSPy GEPA 优化；这里复用其搜索思想，搜索对象换成框架无关的完整策略。

| GEPA 机制                  | 本组件对应实现                                                     |
| -------------------------- | ------------------------------------------------------------------ |
| 真实执行反馈驱动改写       | train 的具体任务、输出、检查、轨迹进入外部反思提示词               |
| 逐任务前沿与覆盖去冗余     | instance 前沿、prune_dominated、按占据前沿频次抽样                 |
| 多目标与多种父选择         | objective/hybrid/cartesian，以及最优、epsilon、Top-K 等选父方式    |
| 轮换组件与联合改写         | round_robin/all；经验按 ID，生成动作／循环规则按类别               |
| 训练批轮换与满分跳过       | epoch 洗牌、末批不补重复题、可选 skip_perfect_score                |
| 同父、独立、P×N 多提案    | 冻结批次计划；all_improvements/best/top_k 筛选改善者               |
| 双亲重组                   | 共同祖先、跨分支组件继承、冲突处理、合并子集验证、全验证及双亲谱系 |
| 中间节点继续进化           | 内部节点和叶节点同样参与选父与重组，不限最新一代                   |
| 小批次接纳和验证复评       | 严格改善或不退化；质量优先；选中提案才执行完整验证                 |
| 相同策略执行缓存           | 精确报告缓存＋逐题补测；版本、split、配置绑定；报告哈希检查        |
| 分组聚合反思               | 可选 ComBEE，分组与汇总调用统一预算、校验、阶段持久化              |
| 请求、试验、时间与停止控制 | 调用数、真实试跑数、截止时间、patience、目标阈值、取消             |
| 搜索状态持久化             | DAG、完整策略、试验、批次计划、阶段与预算可恢复                    |
| 最终生产准入               | 在已有统一评测器上冻结 winner，再做独立 holdout；版本发布和离线包  |

保留的实现差异与交付边界：

- 上游可搜索任意字符串组件；本包只改写已批准经验与授权控制规则，手工策略和宿主程序保持原样。通用打点无需改变。
- 上游常以单一总分比较。本包先保任务质量，再优化无效循环、token、时延；多提案按平均增益排序，避免末批较短造成总分偏置。重组默认要求不差于双亲，也可用 Pareto 模式保留局部优势继续验证。组件冲突平分时采用稳定选择。
- GEPA 的自定义 Python callable、DSPy/LangChain 等框架适配器、编码代理提案器不放入交付依赖；对外继续使用统一协议与配置。引入任意宿主代码改写需要另行定义执行授权和隔离契约。
- 模型提案在后台顺序生成，任务试验按配置并行；不额外引入分布式调度系统。模型调用数、试验数和时间是明确预算，供应商金额换算、WandB/MLflow 等可视化服务不作为搜索核心依赖。
- 发布另有用户、记忆 revision、控制权限和生产父版本检查；搜索分数不会直接覆盖记忆正文、越过授权，或将组合收益归因到每条记忆。

## 验证实现

### 生效归因与选优

训练样本上的实际变化可以支持保留探索节点；最终选优还要求候选相对至少一个父节点，在**验证集实际改变行为的同题样本**上有可归因收益：质量、综合适应度和可比的无效 loop 不退化，有正向增益，并满足已配置的时延比例限制。未触发样本仍计入完整验证成绩，但不能替新增规则证明效果；仅在训练触发过也不能替代验证证据。

节点的 `validation_gain_attributed` 记录这项派生判定，依据为已有 `validation_applied_changes` 与父子同题评分。缺少回执、匹配样本或时延证据时不能靠较高总分通过这项检查。多亲节点逐父比较，不把某个父节点的生效记录移用到另一个父节点。探索保留和发布仍是不同阶段；完整验证与独立留出评测继续执行原门槛，评分权重不变。

这项检查排除“新控制在验证中完全没生效，却因其他题随机变好被选中”的情形；它不是统计因果证明。真实模型有波动，正式收益仍应使用固定版本、相同宿主配置和既定评测协议验证。安全执行或宿主代码发生修复时，应确认已有基线是否仍可比较，不把宿主修复造成的改善算成策略收益。

### 反思可见的控制证据

- `prior_operation_rounds`：相同 run/scope/操作已经落定的尝试轮数，包括成功，异步子动作也参与；派发检查本身不扣次数。
- `terminal_error_code_candidate`：失败返回中的结构化错误码。它是候选证据，不代表所有同类错误都不可重试。
- `schedule_plans.actions.arguments`：有限的共享资源参数，支持生成跨语言的实例依赖规则，不传重复的完整模型历史。
- `schedule_plans.task_text`：该调度点实际用于条件匹配的 run 输入节选。文本条件从这里选择，不能把技能派发 prompt 中的短语当作 run 条件；`__evolution_resource` 的来源和歧义处理见[运行时控制](16-runtime-controls.md)。

生成、运行时、预检和父策略回放共同使用目标账本及资源投影。旧轨迹缺少必要字段时不补造事实。控制规则连同来源和条件保存在策略版本中，导入后不依赖训练目录。

其中 `terminal_failure` 的配置错误按执行分支隔离：相同模型不代表相同业务任务，独立分支的首次调用不会被另一个分支的失败拦截。预检和父策略回放使用同一执行身份，不能用旧的全 run 失败计数为新规则证明可触发。普通同目标重试和总尝试预算仍遵循各自显式参数身份，不受这项隔离影响。

同批试验可以包含采集失败的记录。这类记录保留 `verdict=error` 和原错误码；没有轨迹时控制反馈的 `evidence.runs=[]`、`control_evidence_preserved=false`，不提供可执行规则依据，也不因缺省数组而中断其他正常记录。异常不计为成功或零成本，评分与发布仍检查评测完整性。

### 将动作拦截与循环收尾一起进化

单独减少工具重试可能被下一轮重新规划抵消。轮转选中 `action_rules` 或 `loop_rules` 时，搜索检查同一训练批次中同一 run、execution、actor 和 scope 的已落定证据：存在可执行的终止性错误／重复失败控制机会，并且该分支出现 replan 或重复失败循环，才联合选择这两个组件。节点记录 `component_coupling=same_branch_failure_recovery`。

这一步不增加反思调用，不使用验证／留出题，也不扩展宿主权限。模型在原有授权内联合提出动作规则及分支恢复预算；只改一类也允许，但仍需真实执行验证其收益。兄弟分支或尚未落定的动作不作为联合依据；停止一个分支不等于停止整个 run。预检、父子行为差异、任务评分和发布门槛继续生效。

L1 反思把记忆作为待验证的建议：优化重复核验与删除题目明确要求的核验是两件事。改写需保留验收义务、同时明确适用条件及例外；有害建议可在版本内停用，不直接篡改来源记忆。提示词约束之外，最终效果仍由实际 Agent 的任务验收判断。

