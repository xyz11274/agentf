# 已发布 seed04：四道代表题的成败分析

分析对象是已发布业务 `seed004`，不是 GEPA 节点。电影、发票、签到属于该版本的额外诊断样本，不计入发布500题汇总；充值属于发布500题。这里的“训练”是采集轨迹、提取和发布外置经验，不是训练模型参数。

## 1. 电影推荐＋健康问答：为什么失败转成功？

任务 `QA_GY_WYYL_011`，首轮要求同时推荐电影和回答健康问题，后续继续两轮问答。L0→seed04：严格通过 **0→1**，质量 **2/3→1**，无效loop **8→2**。

**改变发生在获取电影数据和交付结果的执行路径。** L0的电影工具连续三次返回空的 `aiMovieData.list`，最终自行列出片名，但没有交付规定的结构化列表和“核心看点”。后两轮问答通过，首轮漏项导致整题失败。seed在event-15并行派发电影和健康技能，`recommend`取得非空 `UserOutputObject.aiMovieData.list`，最终列出片名、看点，三轮全部满足。电影数据来自工具返回，不是从经验卡中背出标准答案。

**训练材料与发布经验覆盖了什么？** 归档TRAIN有 `GAP012_DELIVER_ACTUAL_RESULTS_01`，专门要求“真实片名＋工具核心看点”。已发布经验 `shared-bbd575…` 的内容是：上游已返回完整、符合约束的结果列表时，直接据此交付，不再额外确认查询。这条规则解决的是“已有结果如何保留和使用”，不提供片名，也不规定本题必须选择哪条查询路线。

**本题说明哪类优化有效？** 工具本身已经能返回合格片单，成功路径使用了这项能力，并完整交付；失败路径反复得到空列表后改成非结构化自答。这里的优化对象是已有工具能力的正确选用、结果保留和输出契约，而不是补充电影知识或背题。已发布规则与成功路径相符，但不能仅凭这个结果给某张卡分配独立贡献。

## 2. 最近一个月话费发票：为什么成功转失败？

任务 `CK_GUI_FHCK_00_004`。L0→seed04：严格通过 **1→0**，质量 **1→0**，无效loop **1→0**。本题要求的是“打开发票页面→选择最近一个月→发起开票”的GUI操作规划。

**错误发生在经验应该作用的前端选路。** L0派给 `device-gui`，交付了完整规划。seed派给 `service-manager`，得到业务未接入的信息，于是只解释不能实际开票、索要抬头和税号等资料。实际派发记录中，期望目标为 `device-gui`，实际目标为 `service-manager`；三个规划必需项全部缺失。不是裁判单纯变严，也不是设备没连接使本题必然失败——L0在同类限制下仍交付了合格计划。

**发布经验没有解决这个决策。** seed04的11条经验涉及计划参数补齐、健康提醒与记录、推荐结果使用、知识检索、偏好保存等；没有“发票操作规划应选择GUI，而不是业务能力查询”的路由规则，也没有在派发边界部署相应的可执行纠偏控制。计划参数经验 `shared-19ca…` 规定的是调用 `plan` 时同时传 `query` 与 `title`；选错技能后，这条参数经验不能补出GUI计划。

**深层缺口是经验作用位置与错误位置不匹配。** 此题首先需要正确识别“规划交付”和“真实开票”，并选中能生成规划的技能。现有经验主要修工具已选定之后的局部行为，未覆盖这里的路线选择。后续执行很快结束，loop降到0，但结束的是一个没有完成交付目标的分支。

## 3. 酷狗每日签到：计划已生成，为什么仍然失败？

任务 `CK_GUI_FHCK_00_061`。L0→seed04：严格通过 **1→0**，质量 **1→0**，无效loop **10→0**。seed正确派发了 `device-gui`，工具已经生成计划；最终却只写“已生成完整的操作计划”“我现在直接回复用户”，没有列出步骤。

**当前训练材料覆盖该缺口，但不能倒推当时已经学过。** 归档训练题 `GAP012_COMPLETE_PLAN_DELIVERY_01` 要求逐项展示步骤、缺项和未执行状态，其 `source_task_ids` 包含本题，且标记为参考评测反馈构造；`GAP014_SEARCH_FAVORITE_CHECKIN_02` 也要求无设备时交付签到步骤。这证明当前已有对应补充材料，不证明它们在seed发布前已经采集、批准或应用。

**当前权威记忆与发布策略的状态不同。** 候选 `candidate:1479f918…` 记录了一条成功轨迹：生成完整6步计划，协调器逐条展示，明确planned且未执行。其建议是“基于skill结果生成最终答复并逐条列出taskPlan.steps，不再重复派发”。当前状态为 `INSUFFICIENT_SUPPORT`：只有 **1条Dialogue、2条Episode**，门槛为 **2条Dialogue、2条Episode**。发布策略的11条正文没有这条完整交付规则；候选区存在正确规则，不等于发布seed已获得该规则。这里不把当前候选状态倒推为本次评测前的审批原因。

**运行侧还存在“知道规则但未落实”的问题。** seed最终回复主动复述了“必须逐条列出taskPlan.steps”，说明本次并非完全不知道交付要求；它把“准备回复”的说明当成了最终回复。运行记录为正常结束，交付物却缺失，直到评分才发现。

因此，本题能够直接确认的失败原因是：**工具能力和计划结果均已具备，模型也复述了交付要求，但最终结束没有保证计划真正交给用户。** 补充同主题训练不能替代末段交付校验；是否学过相似题、哪张经验导致这次行为，不能仅凭当前归档材料认定。无效loop下降，但没有补齐缺失交付。

## 4. 指定88元话费充值：成功究竟是不是经验的功劳？

任务 `CK_GUI_FHCK_00_003`。L0与seed均严格通过、质量1、无效loop0。两份完整记录的根题干逐字相同，首轮请求的模型、工具定义和8192输出上限相同；系统当前时间相差两小时。

**成功条件在L0中已经存在。** L0先检查设备，再生成充值计划；seed先生成计划，再尝试execute。两边 `taskPlan.steps` 逐字相同，都覆盖充值页面、号码、88元金额及确认提交。该题验收要求规划交付，因此两边都通过。计划能力和结果交付规则不需要依赖本题新增经验才能成立。

**实际应用的经验无法解释前段规划。** seed唯一应用的卡是 `shared-5a15…`，正文要求“按用户指定内容写入记忆，回读验证”。GUI结果在event-65已返回，经验应用回执在event-80，属于后续协调回复阶段；前面的派发和规划已经发生。这张卡与充值参数也没有对应关系。不能把前段动作差异、相同计划或本题通过说成这张卡带来的改善。

**相似训练与真实能力也应分开。** 归档TRAIN有“联通APP充值30元、缺手机号与支付方式、仅规划”的 `GAP012_FAILURE_BRANCH_AND_MISSING_FIELDS_01`。但本题两边均 `device_connected:false`，seed的execute返回 `unsupported`，缺少手机与自动化适配器，没有实际扣费。相似题和经验都不能生成不存在的执行条件。

这题是对照：**原有能力已经能完成规划；不相关经验在结果产生后应用；真实执行缺口仍然存在。** 将它算作经验促成的新成功，会把原有能力、提示应用和真实操作混在一起。

## Hermes相关事务

这四题对应的可借鉴机制是把步骤、易错点与完成验证连在一起。[Hermes官方技能文档](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills/)的技能载体允许写Procedure、Pitfalls、Verification，并携带脚本和参考资料；[官方学习路径](https://hermes-agent.nousresearch.com/docs/getting-started/learning-path/)另有可选模型训练通路。我们的上述发布版本主要改变外置经验，不更新模型参数。机制差异不能直接证明在同一数据集上的性能优势，因此本文不编造“Hermes在这些题上一定更好”的因果结论。

核对依据为同版本逐题指标、保留的配对运行/裁判记录、归档TRAIN和权威候选记忆。相似训练题的存在、规则内容与实际执行变化分别陈述，不把它们自动等同为因果关系。
