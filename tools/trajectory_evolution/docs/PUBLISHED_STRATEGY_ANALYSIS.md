# 已发布策略seed04：四道代表题的执行与原因分析

本文分析已发布的业务策略`seed004`，对照不使用这些经验的L0。选取电影推荐、话费发票、每日签到、话费充值四题，分别说明结果怎样产生，以及能否归功于经验。前三题是该版本的额外诊断题，充值题属于发布500题；这里不把四题汇总成整体提升比例。

电影、发票、签到的分析依据是保留的逐轮裁判记录、最终答复及技能派发记录；充值还保留了完整的两份执行记录。执行结果与“经验造成了这个结果”是两件事：下面分别回答，不把注入次数当成经验有效的证明。

## 1. 电影推荐与健康问答：失败转成功，关键是拿到片单并答全

题号：`QA_GY_WYYL_011`。任务包含电影推荐和健康问答，后面继续两轮问答。电影部分要求给出电影列表和核心看点，不能只写几个片名。

| 指标 | L0 | seed04 |
|---|---:|---:|
| 严格通过 | 否 | 是 |
| 质量 | 2/3 | 1 |
| 无效loop | 8 | 2 |

**执行过程。** 保留的裁判记录记载了以下步骤：

| 步骤 | L0 | seed04 |
|---|---|---|
| 获取电影信息 | 三次电影查询都返回空的电影列表，记录对应event-31、53、79 | event-15同时派发电影和健康技能；电影技能的recommend取得有效片单 |
| 处理结果 | 没有拿到合格片单，最终自行列出片名 | 使用工具返回的《肖申克的救赎》《地球脉动》《星际穿越》等结果 |
| 交付给用户 | 缺少规定的电影列表和核心看点 | 给出片名及看点，同时完成健康问答 |
| 后续两轮 | 都通过 | 都通过 |

**为什么评分改变。** L0不是三轮都做错，而是首轮电影部分漏项，因此质量是2/3，整题严格通过为否。seed把首轮漏掉的内容补齐，三轮都通过。改善来自两个具体变化：先拿到了合格工具结果，再把结果完整交给用户；不是学会了几部电影的名字。

**训练和经验补到了什么。** 当前归档训练集有“给出真实片名和工具提供的看点”的类似题。发布经验也提醒：工具已经返回完整结果时，直接使用，不要再额外查询。但这条提醒主要处理“有结果以后怎么答”，没有规定本题前面必须选择recommend。

**是经验的效果，还是模型本次执行不同？** 本题记录有9次经验应用，但没有保留下每次是哪条经验、何时进入模型消息。可以确认seed的执行路径更好，不能确定选择recommend是经验教会的，也不能确定最后答全必然由某条经验促成。准确结论是：**这是一次真实的失败转成功，改善位置明确，经验的独立贡献尚未得到验证。** 不能直接把它宣传成“注入了某条经验，所以多做对一题”。

**应当补什么。** 训练要同时覆盖两段：空片单后怎样换合适的查询，以及拿到结果后怎样按要求交付。只训练最后如何组织答复，无法解决前面一直查不到结果的问题。

## 2. 最近一个月话费发票：成功转失败，错误发生在选技能时

题号：`CK_GUI_FHCK_00_004`。本题检查的是开票操作计划，必须包含打开发票页面、选择最近一个月、发起开票三个步骤。

| 指标 | L0 | seed04 |
|---|---:|---:|
| 严格通过 | 是 | 否 |
| 质量 | 1 | 0 |
| 无效loop | 1 | 0 |

| 步骤 | L0 | seed04 |
|---|---|---|
| 选择技能 | 派给device-gui | 派给service-manager |
| 得到的方向 | 生成GUI操作计划 | 查询业务能否办理，得到业务未接入的信息 |
| 最终答复 | 交付完整开票计划 | 解释不能办理并索要抬头、税号等资料 |
| 完成检查 | 三个必需步骤都有 | 三个必需步骤都缺失 |

**为什么失败。** 这不是少写一个字段，而是一开始走错了路线。seed走的是业务办理路线，后续答复也沿着“业务没接入、还缺资料”继续，没有回到本题需要的GUI计划。L0已经证明，设备限制并不妨碍交付这份计划，所以不能把失败归为设备没连接或环境不支持。

**经验为什么没把它拉回来。** 发布包的11条经验没有“此类开票规划应选择GUI技能”的提醒。已有计划经验只要求调用plan时带齐query和title；如果根本没有选中GUI技能，这条参数提醒就帮不上忙。能确认的是**这版策略缺少针对选路错误的有效经验**，不能据此说整个训练集完全没有发票题。

**是不是经验把模型带偏了？** 本题记录有1次经验应用，但没有那次应用的正文和注入后的模型消息。因此不能证明经验导致了选错，也不能把这次错误简单归为纯随机。能确定的原因是选错技能后没有纠正，最终交付物不符合任务要求。**无效loop从1降到0只是更快结束了错误分支，不是任务做得更好。**

**应当补什么。** 补充成对训练：同样涉及发票，一类要求生成APP操作计划，另一类要求真实办理业务；训练派发时如何区分，并检查最终是否给出三步计划。只补plan参数格式，修不到本题最早发生的错误。

## 3. 酷狗每日签到：成功转失败，工具做完了，用户却没收到

题号：`CK_GUI_FHCK_00_061`。本题需要把签到操作计划逐步交给用户。

| 指标 | L0 | seed04 |
|---|---:|---:|
| 严格通过 | 是 | 否 |
| 质量 | 1 | 0 |
| 无效loop | 10 | 0 |

| 步骤 | L0 | seed04 |
|---|---|---|
| 选择技能 | device-gui | device-gui，选择正确 |
| 生成计划 | 得到签到计划 | 裁判记录确认已经生成计划 |
| 最终答复 | 列出了五步操作 | 只说“已生成完整的操作计划”“我现在直接回复用户” |
| 完成检查 | 用户收到实际步骤 | 没有列出步骤，交付失败 |

**为什么失败。** 本题不是工具不会生成计划，也不是模型不知道要列步骤。seed的答复自己复述了“必须逐条列出taskPlan.steps”，却把“准备回复用户”的说明当成了最终回复。也就是**知道要做什么，工具也给了材料，但结束前没有检查自己到底做没做。**

**是不是缺训练数据？** 当前训练集已经补了逐项展示计划、说明未执行状态的类似题，其中有根据本题评测反馈构造的材料。因此不能说现在没有对应训练，也不能把这些后来整理的材料当成seed发布前已经学过的证明。

权威记忆里还保存着一条正确的候选经验：工具生成完整六步计划后，协调器逐条展示，并明确没有实际执行。它当前只有1条对话支持，现有批准要求是2条对话，所以仍未批准。发布包的11条经验也没有这条完整交付提醒。**候选库有正确经验，不等于发布策略已经能用它。** 当前候选状态不能倒推为这次历史评测时的审批原因。

**这次退步是经验导致的吗？** 本题有2次经验应用，但缺少对应正文和模型消息，无法确定哪条经验影响了结束行为。已经可以确定的失败机制是“把工具完成当成用户收到”，不能据此证明经验导致退步，也不能证明加一句提醒就一定解决。无效loop降到0，仍然没有完成交付。

**应当补什么。** 用不同真实对话采集“生成计划后完整展示”的成功记录，让正确经验达到批准要求；同时在结束前检查答复里是否真的有步骤。训练和完成检查都要补，单纯告诉模型“记得回复”不够。

## 4. 指定88元话费充值：两边都通过，前段变化可以排除那条经验

题号：`CK_GUI_FHCK_00_003`。两边严格通过，质量都是1，无效loop都是0。评分通过的是充值操作计划，不是已经付款。

这一题保留了完整配对记录，可以检查模型输入与经验出现的时间。两份根请求逐字相同，首次协调器调用的模型、工具定义、8192输出上限相同；系统当前时间分别是15:33:23和17:33:23。去掉时间后，首次消息内容相同，当时还没有应用这条经验。

| 步骤 | L0 | seed04 |
|---|---|---|
| 协调器委派 | 要求先检查Android设备；能执行则执行，不能执行则给完整计划 | 要求真实执行并回读；缺执行条件则给计划和缺项 |
| GUI技能第一步 | 检查设备，发现未连接 | 先生成充值计划，结果也说明设备未连接 |
| 后续动作 | 生成计划；把skill_result误当工具动作，校验拒绝后改用文本交付 | 已说明不能点击，仍尝试execute，返回unsupported及缺少执行能力 |
| 最终交付 | 给完整计划并说明未实际充值 | 给完整计划并说明未实际充值 |
| 最终评分 | 通过 | 通过 |

**为什么两边都能成功。** 两边六步计划逐项相同：进入充值页面、填号码、填88元金额、确认提交等。生成这些步骤的能力本来就存在于GUI工具里，原有技能说明也要求把planned结果逐项交付。两边最后都给出计划并如实说明未执行，所以通过。**不是经验新教会了充值，也没有发生实际扣费。**

**为什么走了不同路径。** 最初的协调器输入尚未注入经验，但它生成了不同的委派文本。技能随后接收的要求不同，才分别走成“先查设备”和“先做计划、再尝试执行”。seed在知道设备未连接后仍调用execute，是动作没有遵守已知状态；不能说它缺少设备信息。仅两次运行不能区分采样波动、服务变化或时间字段的影响，但可以确定前段变化不是后面那条经验造成的。

**经验在什么时候出现。** seed唯一实际应用的经验是“按用户要求写入记忆并回读验证”，与充值计划无关。GUI结果在event-65已经返回，经验应用回执在event-80；正文进入的是最后汇总阶段的协调器消息。前面的委派、计划和执行尝试都已经发生，所以这条经验无法导致那些动作。

**归因结论。** 这题能明确回答：**通过来自原有工具和正常计划交付；前段路径变化来自经验注入之前的模型委派差异。没有新增通过题，也没有证据表明这条记忆经验提升了本题效果。** 它最多可能影响最后的措辞，不能被用来解释充值步骤或得分提升。

## Hermes能借鉴什么

[Hermes官方技能文档](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills/)把操作步骤、常见错误和完成检查放在一起，还可以附带脚本。这里值得借鉴的不是“换一套数据就一定更好”，而是让经验覆盖实际执行：前面选对技能，中间按设备和工具状态采取动作，最后确认结果真正交给用户。

四题说明了不同缺口：电影要补获取结果和完整答复；发票要补技能选择；签到要补最后交付；充值则不能把原有能力算成经验的新收益。要进一步证明经验贡献，需要在同题、同模型设置下，对目标经验启用和关闭分别重复运行。当前没有这样的对照，因此不能宣称Hermes或某条经验已经解决了这些问题。
