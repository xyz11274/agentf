experiences 提供 ID、scope、condition。components 的 experience:ID 可以是正文字符串，或 {content, trigger_pattern, observed_operations} 对象。本次输出非空正文时，即使只改正文，也应复核并显式返回完整 trigger_pattern；当前条件取 components 中非空 trigger_pattern，否则取同 ID 的 experiences.condition。采纳中间建议的条件改动时与正文一并保留，无需变化则原样返回，不为凑改动收窄或扩大；observed_operations 可选，未提供的条件仍继承父版本。content:null 停用时不带 trigger_pattern 或 observed_operations。不得在汇总时丢掉已验证的适用范围。observed_operations 仅以当前分支实际完成的操作为依据，不把建议或计划视为执行事实。

只输出严格 JSON。经验组件：
{"reason":"基于分组证据的汇总理由","experience":{"memory_id":"已批准 ID","content":"完整经验正文","trigger_pattern":"复核后的完整适用条件"}}

<!-- gepa:controls -->

控制组件输出 control_updates 数组，每项包含 component（action_rules、loop_rules 或 schedule_rules）与 op（add、set 或 remove）。add 提供完整规则 value；set 提供父 components 数组的 0 基 index 与完整 value；remove 只提供 index。add 不带 index、remove 不带 value；所有索引始终相对于父数组，同一旧条目只能修改一次。未提到的规则继承，不因汇总一个执行者而删除另一个执行者的规则。不能同时输出 controls 与 control_updates；旧 controls 完整替换格式仅保留接口兼容，本次汇总采用增量格式。

规则 value 沿用 intermediate_proposals 中已验证组件的完整字段，动作/调度/循环能力以输入 controls 的 primitives 与 limits 为准，不虚构新能力。actor_id、require_finalization、error_codes、after_action_rejection、目标参数、失败配置隔离等条件不可在汇总时意外丢失。max_iterations=N 允许第 1..N 轮，只在第 N+1 轮起限制；只有开放 bounded_iteration_cap 时才可降低。controls.aggressive_controls=false 时降低上限，必须保留实际 actor_id 与 require_finalization:true，以及同一执行者的 can_finalize 证据；没有证据就保留原上限，不把有条件收尾合并成无条件终止。手工基础规则不变，不扩大作用域或放松基础上限；没有支持删除的证据就保留原规则。经验正文遵守 limits.max_experience_bytes。
